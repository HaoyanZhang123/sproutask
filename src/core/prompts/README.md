# 提示词层

> **当前生效版本：`v2/`**（`v1/` 已冻结，留作 A/B 对比基线）

## 目录与分层

```
src/core/prompts/
├─ index.ts          # 出口：决定"哪一版生效"（只改这一行）
├─ v1/               # 冻结基线（2026-09 之前的版本，不再改动）
└─ v2/               # 当前生效
   ├─ index.ts        # 汇总各层，导出 PROMPT_VERSION 与 buildMessages()
   ├─ l0-persona.ts   # 身份、语气、反 AI 腔清单
   ├─ l1-discipline.ts# 苏格拉底规则、防抄作业、超纲处理、安全红线、对话节奏
   ├─ l2-textbook.ts  # 教材上下文拼装（课标 + 教材原文 + 知识点）
   ├─ l3-profile.ts   # 学情摘要（掌握度、重复出现的误区）
   └─ l4-session.ts   # 会话上下文（学习模式与位置、已用提示次数）
```

## 版本规矩（防止版本越堆越乱）

1. **同一时刻只有一个版本生效**——切换只改 `src/core/prompts/index.ts` 的那一行 `export * from './vN'`
2. **旧版本冻结**：不再改任何一个字（它的价值就是"对比基线"，改了就没法比）
3. **只保留"当前版 + 上一版"**：将来出 v3 且 v1 不再需要对比时，**删掉 v1**
4. 新版本 = 复制上一版整目录再改（保证未改动的层逐字节一致），并在文件头写清"这一版相对上一版改了什么"
5. 改教学规则/语气**必须**升级版本；纯修错别字可以原地改

## 约定

- 每层一个文件、导出字符串常量或拼装函数；**禁止在业务代码里内联提示词**
- 提示词文本是"教学内容"而非代码，允许中文并写清教学意图注释
- 每个版本都跑 `evals/cases/`：改动前后必须跑 `pnpm eval` 对比（报告落在 `evals/reports/`）
- 想直观比较两版语气：`pnpm prompts:compare`（同一批问题分别用 v1 / v2 生成，并排打印）

## v2 相对 v1 改了什么（2026-09，用户反馈"AI 味太浓"）

| 层 | 改动 |
|---|---|
| L0 | 新增**反 AI 腔清单**（禁自我介绍式开场、禁空洞客套、禁"首先/其次/总之"、禁重复学生的话来确认、禁排比与宣传腔）；**类比不得替代或偏离教材说法**（用户要求以课本原文为准） |
| L0 | **（验收期修订）新增"说话的温度"一节**：先用一句话接住学生 → **用邀请代替命令** → 禁用"没意思/不行/不对/别问了"等冷硬推拒说法 → 长度 **100–180 字**（宁可多一句温暖的话，也不要为了干脆而冷淡） |
| L1 | **删掉写死的台词**（v1 直接给整句话，模型会反复背）→ 改为说清"要做什么"；修正过期示例；新增"必须以提问收尾""不要直接确认或纠正学生""不要把答案的要点/条数/结构先说出来" |
| L2/L3/L4 | **未改**（与 v1 逐字节相同） |

> **为什么 v2 是原地修订而不是再开 v3**：v1 已冻结（基线），而 v2 尚未被用户验收通过，仍处于
> "验收期迭代"。版本规矩里的"冻结"针对**已验收/已被取代**的版本；等 v2 被认可后需要再改时，才新开 v3。
> 验收期内的修订记录在各文件头部与本表。
