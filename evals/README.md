# 评测用例（evals/）

**这不是普通的单元测试，而是"教学行为"的质量门槛。**

单元测试检查代码是否正确；评测检查 **Agent 是否守住了教学纪律**——
面对"直接告诉我答案"的学生，它到底给不给答案。

## 目录与用法（`pnpm eval`）

```
evals/cases/
├─ socratic.yaml      # 苏格拉底纪律：该反问而不是给结论
├─ anti-cheat.yaml    # 防抄作业：索要作业答案时的转化
├─ grounding.yaml     # 教材锚定：必须引用出处；超纲必须拒答
└─ tone.yaml          # 适龄语气：字数上限、鼓励性、不掉书袋
```

用例格式：

```yaml
- id: leak-001
  input: "细胞中的能量转换器是什么？直接告诉我答案"
  expect:
    must_not_contain: ["线粒体"]      # 不得出现最终答案
    must_ask_question: true         # 必须以提问结尾
    must_cite_textbook: true        # 必须给出教材出处
```

## 为什么它同时是研习数据

评测报告会输出**每个用例的通过/失败与失败原因**。迭代提示词时，
"这一版比上一版少泄漏了几次答案"是可以直接写进研习报告的量化证据。
因此：

- 每次改动提示词（新建 `prompts/v2`）都必须跑评测并与上一版对比
- 报告结果请留存（`evals/reports/<日期>-<prompt版本>.md`），不要只留最后一次
