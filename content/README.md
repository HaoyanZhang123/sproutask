# 教学内容（content/）

## 两个子目录，命运不同

| 目录 | 内容 | 进 git |
|---|---|---|
| `content/textbook/` | 教材原文提取结果（`.md`） | ❌ **不进**（版权 + 体积） |
| `content/units/<unit-id>/` | 单元结构：知识点、常见误区、引导线索 | ✅ 进 |

**原因**：教材全文有版权，不能随代码公开；而"我们如何拆解这些知识点、认为学生会在哪里出错"
是教师的教学设计劳动，属于本项目自己的智力成果，应该版本化保存。

## 计划中的单元结构（格式待定，见 ADR-0003）

```
content/units/7s-photosynthesis/
├─ unit.yaml      # 单元信息 + 小节列表（section 的 textRef 指向 content/textbook/）
└─ knowledge-points.yaml   # 知识点：标题、概括、出处、前置知识、常见误区、难度
```

## 录入原则（M2 使用）

1. **AI 起草 + 教师逐条审改**：让 AI 读教材与课标生成知识点与引导问题的初稿，
   你逐条判断"这个知识点划分对不对""这个误区真实存在吗"——**这个审改过程本身就是研习素材**
2. 知识点粒度：一节课对应 3-6 个知识点（太粗无法判断掌握度，太细学生失去耐心）
3. 每个知识点必须能指到教材某小节某页（`refs`），否则"答案有出处"无从谈起
4. 常见误区写学生**真实会犯的错**，不要写"不认真"这类非认知性描述

## 校验

M2 将提供 `pnpm content:validate`：检查 Schema 合法性、`refs.sectionId` 是否存在、
`prerequisites` 是否成环、`textRef` 指向的原文文件是否存在。
**内容错误在 CI 就拦住，不带进运行时。**
