# ADR-0001：采用"本地优先的桌面 Agent"架构

- **状态**：Accepted
- **日期**：2026-09
- **决策者**：项目维护者（需求方拍板）

## 背景

产品要面向初中生做"教材锚定的苏格拉底式学习助手"。曾评估过四类形态：
① Web 网页端；② Electron 壳 + 自架云端后端；③ 群聊机器人/小程序；④ 纯本地桌面 Agent。

## 决策

采用 **④ 本地优先的桌面 Agent**：

- Agent 运行时（目标、学情状态、工具调用、教学策略）全部内置在安装包里，跑在 Electron 主进程
- DeepSeek API 仅作推理外脑，是**唯一**的云端依赖
- 教材原文注入上下文，**不做向量检索**（单单元 1-2 万字，64K 上下文足够；配合上下文缓存几乎零成本）
- 学情与日志存本地（**2026-09 修订**：曾考虑"教师笔记本作基站"做局域网聚合，已随"不做教师端"一并移除）

## 理由

1. 需求方明确否决 Web 与"云端套壳"形态
2. 机房电脑常无管理员权限 → 免安装便携 exe 是可行路径；网页端反受校园网白名单限制
3. 单单元规模下检索是多余复杂度：注入全文更简单、更可靠、还能让 Agent 看到概念间的前后关系
4. 少一个云端依赖（无服务器月租、无第二家 API），对手工维护更友好
5. 数据不出本机，合规叙事更强（未成年学生数据）

## 被否决的选项与理由

| 选项 | 否决理由 |
|---|---|
| Web 网页端 | 需求方不要；且校园网白名单可能拦截 |
| Electron 壳 + 云端后端 | 需求方视为"云端套壳"；多一台服务器的成本与运维 |
| 小程序 / 公众号机器人 | 个人主体无 AI 问答类目资质；学生在校不能用手机 |
| 向量检索（RAG） | 当时判断单单元规模下不需要；2026-09 需求扩为全册后，仍延后（见 ADR-0004） |
| 本地 Ollama 小模型 | 8B 级模型幻觉多、指令遵循弱，与"严格锚定教材"目标相悖（仅可用于断网演示兜底） |
| 教师端（学情雷达 / 教师查看对话） | 2026-09 移除：涉及学生隐私，本项目不做 |

## 后果

- ✅ 只有一个云端依赖与一个 API Key，运维最简
- ✅ 离线也能查看教材原文；联网仅用于"思考"
- ⚠️ API Key 由使用者自行配置、**只存本机**（`.env` 或打包后的用户配置文件）→ 若被他人拿到本机可读取，故建议：充值制封顶 + 随时吊销；本项目**不做**多人共享 Key 的形态
- ⚠️ 对话日志分散在各学生电脑 → 对策：本地存储；数据本地留存与匿名化导出
- ⚠️ 范围扩到全册教材后，不能再"整段注入" → 改为**结构化按需装载**，见下方修订

## 修订记录

### 2026-09：教材接入方式由"整单元整段注入"改为"全册结构化入库 + 按需装载"

**变更原因**：需求明确为"全册教材入库，根据学生学到哪里提取对应内容，并把课程标准等教学材料
一并放入以防止 AI 跑偏"。单单元整段注入无法满足"全册入库"。

**变更内容**：
- 教材**全册**结构化入库（册 → 章 → 节 + 知识点 + 课标映射）
- 运行时按 `StudyPosition`（学生自选位置）装载对应章节原文，**不是**把全书塞进上下文
- 新增**课标约束层**（L2），随上下文注入
- 向量检索仍在**延后**状态（见 ADR-0004），当前推荐"结构化按需装载"

**不变的部分**：本地优先、API 只作外脑、单一 DeepSeek 依赖、不做教师端、数据存本地。

### 2026-09：交互形态与"教学进度"依赖的调整

- 原设计"Agent 知道这周教到哪、主动推进"→ 改为 **Agent 主动询问 + 学生四选一模式**
  （预习 / 复习 / 做题 / 拓展），不依赖教师排课（更贴合现实）
- 移除 `TeachingPlan`（教学进度表）契约
- 交互形态确定为方案 D（对话 + 可折叠教材阅读视图），见 ADR-0002
