# ADR-0004：教材装载方式——结构化按需装载 vs 向量检索

- **状态**：**Accepted（2026-09 拍板，采纳方案 1）**
- **日期**：2026-09

## 决策（2026-09）

1. **采纳方案 1「结构化按需装载」**：全册教材按 `册 → 章 → 节` 结构化入库，
   运行时按学生当前位置装载对应章节原文注入上下文；**不做全文注入、暂不做向量检索**
2. **向量检索延后**：若将来确有跨章节检索需求，先用 jieba 关键词检索（零额外 API）过渡
3. **课标约束与检索方式无关**：课标要求按当前单元/知识点**精确映射后随上下文注入**（L2 层），
   并在提示词中明确"不得超出教材与课标范围"
4. **学习位置**：**自动恢复上次位置 + 可手动修改**
   —— 首次由学生选择（册·章·节），之后默认回到上次位置，界面提供入口随时切换


## 背景

2026-09 的需求表述：把初中生物**全册教材**（如人教版）喂给 AI，"做成一个向量库，或者反正就是把它
提取出来存在里面"，然后**根据学生学到哪里就提取对应的**；同时把**课程标准和其他教学相关材料**
也放进去，防止 AI 自己跑偏。

这带来两个必须回答的问题：
1. 全册教材体量远大于单单元（初中生物四册，正文估计 40-60 万字），**不可能整册塞进上下文**；
2. "根据学到哪里提取对应内容"——这个"提取"是**按结构取**（学生位置已知，直接取对应章节），
   还是**按语义检索**（向量库，按问题找相关片段）？

## 三个候选方案

### 方案 1：结构化按需装载（推荐）
- 全册教材按 `册 → 章 → 节` 结构化入库，建立索引 + 知识点 + 常见误区 + 课标映射
- 运行时由 `buildStudyScope(position, mode)` 把**当前位置对应的教材原文**（一节或一章）整段注入上下文
- ✅ 无需 embedding、**无需第二个 API Key**（延续"只有一个 DeepSeek Key"的简洁性）
- ✅ 内容完整、无"检索不到/检索错段落"的问题；AI 能看到概念间的前后关系
- ✅ 学习位置已知（学生自选模式时确定），"按位置取"完全够用
- ⚠️ 需要学生/教师先确定位置（学生自选 册·章·节，或从上次进度恢复）
- ⚠️ 跨章节的模糊提问（"细胞和遗传有什么关系"）拿不到其他章节原文

### 方案 2：向量检索（RAG）
- 全册切块 → embedding → 向量库；按学生问题检索 Top-K 片段注入
- ✅ 支持跨章节、开放式提问；不依赖"当前位置"
- ⚠️ 需要 **embedding 服务**（智谱/通义/本地 BGE）—— 用户曾明确希望去掉额外 API
- ⚠️ 引入检索质量风险（检索不到 → 答非所问；检索错段落 → 幻觉）
- ⚠️ 教材被切碎后，AI 看不到概念间的连贯结构

### 方案 3：结构化装载为主 + 向量检索为辅（备选，可延后）
- 默认走方案 1；仅在"跨章节提问 / 复习模式全册搜索"时启用检索
- ✅ 兼顾两者；⚠️ 复杂度最高

## 推荐

**先做方案 1**，保留方案 3 作为后续增强。理由：

1. 需求本身（"按学到哪里提取对应的"）就是**按位置取**，方案 1 直接命中
2. 保持"项目只依赖一个 API Key"的简洁性——少一个外部依赖就少一类故障与合规问题
3. 方案 1 的内容资产（章节结构 / 知识点 / 课标映射）是方案 2 的**前置条件**：
   即便将来上向量检索，也要先把教材结构化，所以方案 1 的工作不会白做
4. 若后期确实需要跨章节检索，可先用 **jieba 关键词检索**（零 API）过渡，再考虑 embedding

**课标约束层的处理**（无论选哪个方案都一样）：
课标不以"检索"方式使用，而是**按当前单元/知识点精确映射后随上下文注入**（L2 层），
并在提示词里明确"不得超出课标与教材范围"——这才是"防跑偏"的关键，与检索方式无关。
