# F-010：最小对话界面（Electron 窗口）

- **里程碑**：M3（M3 收尾，做完即达到开源发布标准）
- **状态**：✅ 已完成（2026-09）
- **依赖**：F-007（意图询问）✅、F-009（Agent 循环）✅

## 1. 目标

把终端里已经跑通的能力搬进桌面窗口：**开场主动询问 → 学生选模式 → 对话 → 看到回复**，
并且整个过程可以被机器自动验证（不依赖人工点击）。

## 2. 用户故事

作为学生，我打开应用就有人问我想做什么，我点一下就能开始；
作为开发者，我希望界面里**不写教学逻辑**，逻辑改动不必动界面，也不必手工回归点击。

## 3. 输入与输出

| 项 | 说明 |
|---|---|
| 输入 | 学生点击模式、输入文字 |
| 输出 | 对话气泡、模式徽章、诊断信息（工具/护栏/降级/迭代轮次） |
| 涉及契约 | 无新增；复用 `ChatSession`、`AgentTurnResult` |

## 4. 实现要点

- **状态机放 core**：`src/core/agent/session.ts` 的 `ChatSession` 持有"模式/位置/历史"，
  在无 Electron 环境下可单测；**main 只做 IPC 校验与转发**，渲染进程只做显示
- IPC：`session:start` / `session:chooseMode` / `agent:chat` / `session:state` / `config:status`
  （`config:status` **只回布尔**，API Key 永不进入渲染进程）
- 主进程自己加载 `.env`：electron-vite 只注入带前缀的变量，不读的话 `pnpm dev` 会一直走降级路径
- **不做逐字流式**（决策与理由）：护栏可能在回答产出后要求重写，逐字显示无法撤回；
  本版显示"正在想…"，护栏通过后整段呈现。流式与护栏的正式取舍留给后续界面迭代
- **界面自检**：`SPROUTASK_SELFTEST=1 pnpm dev` 会在真实应用里操作 DOM 并断言，失败以退出码 1 结束

## 5. 验收标准

- [x] 开场展示主动询问与四个模式按钮；点击后进入对话态并显示当前模式
- [x] 学生消息与回复都能上屏；无 Key 时显示可读降级话术
- [x] 会话状态机（模式/位置/历史/上限）有单测覆盖
- [x] `pnpm typecheck` 0 错；`pnpm test` 全绿
- [x] **界面自检 15 项全过**（DOM 级断言，非人工目视）
- [x] 合规：渲染进程拿不到 API Key；界面不收集个人信息

**实测结论（2026-09-22）**：
- `pnpm test` **90/90 通过**（9 个文件；本次新增 `tests/session.test.ts` 11 例）
- `pnpm typecheck` 0 错
- `SPROUTASK_SELFTEST=1 pnpm dev` → **15/15 通过**：主进程装配 7 项 + 界面渲染 2 项 +
  交互 4 项 + 样式 1 项 + 降级话术 1 项；并输出截图 `selftest-ui.png`
  （其中"样式已生效"用 `getComputedStyle` 断言用户气泡为品牌绿 `rgb(22, 163, 74)`，
  可确认 scoped CSS 真的加载了，而不只是 DOM 存在）

## 6. 明确不做

- 不做教材阅读视图（F-011）、不做折叠答案与出处高亮（F-011）
- 不做持久化（F-013）：关掉应用历史即消失
- 不做多会话、不做设置页、不做无障碍与响应式打磨
- 不做打包分发（F-015）

## 7. 已知缺口与遗留问题

- **诊断信息直接展示在气泡下方**（工具/护栏/迭代轮次）：对开发与研究有用，
  但**面向真实学生需要隐藏或收进"详情"**——发布前应按运行模式区分（M5 配置向导一起处理）
- 流式输出未实现（见上）；学生观感上是"整段出现"，长回答时等待感偏强
- 位置选择在界面上目前只有一处（演示单元只有一节）；多章节选择界面随 M2 内容库一起做
- 渲染进程的类型是手写的，与 preload 需人工保持一致（已在 `env.d.ts` 注明）
