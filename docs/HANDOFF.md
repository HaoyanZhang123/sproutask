## 1. 一分钟了解

**芽问 SproutAsk**：一个**本地优先**的初中生物学习桌面应用（Electron + Vue3 + TypeScript）。
它不是"聊天机器人套壳"，产品主张是两条：

1. **不给答案**——用苏格拉底式提问带学生自己把知识想明白（有"答案泄漏护栏"）
2. **每句话都有出处**——解释只来自教材原文与课程标准（超纲问题拒答并引回课本）

形态：Windows 桌面应用（便携版 exe 已发布）；云端唯一依赖是 DeepSeek API（用户自备 Key）。
**不做**：教师端、班级聚合、查看学生对话（隐私优先）；**不做**网页版。

当前案例单元：人教版《生物学》七年级上册 第二单元第一章第四节「细胞的生活」。

## 5. 怎么跑（命令都在根目录）

```powershell
pnpm install
pnpm dev                                        # 开发模式开窗口（读项目根 .env 里的 Key）
pnpm typecheck && pnpm test                     # 质量门（必须全绿才算完成）
$env:SPROUTASK_SELFTEST="1"; pnpm dev           # 界面自检：真实 DOM 断言 + 截图 + selftest-result.json
pnpm chat                                       # 终端对话
pnpm eval                                       # 教学行为评测（真实调用模型，会产生费用）
pnpm build:win                                  # 打包 Windows 便携版 → release\SproutAsk-0.1.0-win-x64.exe
pnpm prompts:compare                            # v1/v2 提示词语气并排对照（真实调用，费用很小）
```

**四种验证级别**（报告结论时必须说清是哪一级）：

1. `pnpm typecheck && pnpm test` —— 离线、必跑
2. `SPROUTASK_SELFTEST=1 pnpm dev` —— 真实界面 DOM 断言，**无 Key 与有 Key 两种环境都要过**
3. `pnpm eval` / `pnpm prompts:compare` —— 真实调用模型，有费用
4. 打包后再跑一次 —— `release\win-unpacked\SproutAsk.exe` 带 `SPROUTASK_SELFTEST=1`
   （打包版无控制台，看 `selftest-result.json`）

## 6. 审计清单（**你的主要任务**）

> 目标：**独立证伪**下面每一条断言。**不要相信文档，去跑命令、读代码、做对照实验。**
> 每条都给出"去哪儿看 / 怎么证伪 / 期望产出"。

### 6.1 分层铁律是否真被强制

- 断言：`renderer → main → core`；`core` 不得依赖 electron/vue；`src/shared` 零依赖；renderer 不得直接引 core/main
- 看：`tests/smoke.test.ts`、`tests/helpers/layering.ts`
- 证伪：往 `src/core` 投放各种绕过写法（`await import(\`electron\`)`、`require.resolve`、注释包裹、别名路径），
  往 `src/renderer` 加越层 import，给 `src/shared` 加任一 `import` —— 是否都能变红？
  正则把关是否漏了 `.vue`、`tsconfig` 别名（`@shared`/相对路径混用）、动态字符串拼接？
- 产出：**未被覆盖的绕过路径清单**（如果有）

### 6.2 测试是不是"自己判自己"

- 断言：128 例全绿；三条分层把关有效
- 看：`tests/**`；对比 `docs/specs/*` 里"验收标准"与实际断言
- 证伪：找恒真断言（`check(x, true)`、`expect(true)`）；找只测实现细节而非行为的用例；
  找出"声称覆盖但实际没测"的路径（例如：流式 SSE 的边界、护栏的**模型层**、降级的每一种 kind、
  `config:save` 的非法输入、打包版与开发版行为差异）
- 产出：**测试盲区清单** + 哪些断言其实什么都没验证

### 6.3 打包与发布是否可复现、可解释

- 断言：`pnpm build:win` 产出 72 MB 便携版；asar 内只有 `out/**` + `package.json` + 生产依赖；
  Release 附件与本地文件 SHA256 一致
- 看：`electron-builder.yml`、`docs/specs/F-015-*.md`、`publish/`
- 证伪：**自己重新打包一次**；用**正规 asar 解析器**（不是字符串搜索）列出包内清单，
  找是否有 `.env`、研究材料、教材原文、测试文件、无关依赖；
  检查 `signAndEditExecutable: false` 的副作用（exe 未改写版本信息/无签名）；
  检查 Release 附件与 `win-unpacked` 是否同源；检查在**干净机器**上能否跑（我没验过）
- 产出：打包可复现性结论 + 包内容审计

### 6.4 密钥与隐私

- 断言：Key 只存在于主进程；界面永不回显（连掩码都不给）；公开放范围不含研究材料
- 看：`src/main/config`、`src/main/ipc`、`src/preload`、`src/renderer`
- 证伪：全链路搜 key 的传递；检查是否有 IPC 通道能把 key 回传；
  检查日志/异常（`boot.log`、`selftest-result.json`、`selftest-ui.png`）是否可能含 key 或个人信息；
  `git log --all -p | Select-String 'sk-'` 找历史泄漏；确认 `.env` 从未入库
- 产出：密钥/隐私风险清单（这是教育项目最不能出错的部分）

### 6.5 教学正确性（**我最没把握、最需要外部判断的部分**）

- 断言：v2 守住纪律（不直接给答案、不预告答案结构、必须提问、必给教材位置），且语气温暖耐心
- 看：`src/core/prompts/v2/*`、`evals/cases/*.yaml`、`evals/reports/*`（v1/v2 对照）
- 证伪：**自己设计 10 条新的学生提问**（不限于现有 15 条用例），真实跑一遍，看：
  - 会不会编造教材没写的内容（幻觉）？
  - 会不会把结论说出来（尤其"学生答错时"）？
  - 会不会把教材位置说错？
  - 遇到"我要抄答案""我好笨""聊游戏"这些边界，处理是否得体？
- 还需要教学法层面的独立判断：**"不直接纠正学生的错误概念，把判断交回课本"**这个策略，
  对真实初中生是否会失效（学生可能翻不到、失去耐心）？现有护栏与纪律是否自相矛盾？
- 产出：教学法评估 + 提示词改进建议（**这是整个审计里最有价值的部分**）

### 6.6 文档与代码是否一致（历史上出错最多的地方）

- 断言：`docs/PROGRESS.md` 每条声明都能追到代码或命令输出
- 证伪：随机抽 5 条"已完成"，逐条找证据并**独立复现**；
  检查公开 README 的状态表是否与代码一致；检查 specs 的"实测结论"是否真能复现
- 已知历史：曾有两处**过度宣称**（"教学内容 进行中"实际是没开始；"评测已完成"其实从未真跑）
  和一处**低估**，均已修正 —— 但这类错误容易再犯，请重点抽查
- 产出：不一致清单（位置 + 原文 + 实际）

- 我自报的弱点（欢迎确认或推翻）：

## 7. 作者自报的"可能出错的地方"（给我挑错）

8. 我曾因没检查退出码而**绕过发布闸门一次**（已修流程，但请确认现在的脚本不会再次发生）
