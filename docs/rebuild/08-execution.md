# 单主对话执行与子智能体调度协议

> 用户2026-10-29最新修正：只给一个主对话提示词，由主智能体自动开子智能体并持续完成全部工作。任务卡是内部工作包，不要求用户逐张派发。复制入口为[总控提示词](MASTER-PROMPT.md)，子任务用[子智能体模板](SUBAGENT-PROMPT.md)。本次写文档不等于已授权当前对话实施产品。

## 1. 权威顺序与授权

后续用户把总控提示词交给主对话并明确执行，即为整套工作包中可逆实现、隔离验证、必要依赖/新education目录的任务范围授权，不逐任务重复问确认。先服从系统/开发者工具规则，再服从用户最新明确指示，再按本交接包产品契约→数据/系统契约→验收→工作包；旧架构/旧需求冲突处仅约束旧代码。新工程不得无记录扩张到其他学科交付、教师端/云同步/任意系统控制。

总控提示词没有授权公开发布、push/merge/Release、购买订阅、外部账户注册、挪用凭据、删除旧代码/数据、修改已安装DSH。预算尚缺时不能先花钱；源PDF未找到不能从个人盘广扫或擅自下载。外部阻塞按第7节处理，不能以它为由停止所有独立工作。

## 2. 开工和恢复

1. 核实当前工作目录、工具/子智能体能力、Git状态，读取[入口](00-START.md)及R01–R18；阅读本轮派发所需规范，不反复重做旧项目审计。
2. 读取[工作包清单](tasks/index.json)与已有reports，不以对话记忆猜“上次做到哪”。首次无报告所有任务为待执行；有报告必须核代码/文件指纹与依赖，过期报告需重验。
3. 主智能体在[唯一工程进度](../PROGRESS.md)的重构区维护调度摘要：任务→状态→owner/agent target→依赖→报告→代码指纹→阻塞。不得由多个子智能体并发写PROGRESS。任务清单是静态规格，不存第二套进度。
4. reports/Txx.md是任务交回证据，不与总体状态互相冒充。工具的task board如可用仅作运行锁，文档报告仍是跨对话恢复依据。
5. 有持久goal工具则建立“实现01范围并通过07全部本期AC”的目标，恢复时按工具规则重新激活；没有则同样持续推进，不能把缺goal工具当功能阻断。
6. 对已有活跃agent/job登记target/id与写入scope。恢复先查状态/收消息，不重复派出同一写任务；失联后先确认旧owner不再写，再收回scope。后台job必须收取结果或取消，不遗留重跑。

## 3. 主智能体职责

主智能体是调度、契约、集成与验收负责人：持续找ready工作包，检查前置产物，生成自足子提示词，登记独占写scope，启动，收回证据，复核并返工，推进后继。不能把“已开子智能体”当任务完成，也不能只给计划后结束。允许主智能体执行本应由其承担的串行集成、文档路由、全局测试；不得同时和某子智能体改同一scope。

每次循环：收消息/作业结果→验证新产物→更新真实状态→找ready且scope不冲突任务→补充输入/启动→自己处理集成或未委派工作→无独立工作时使用环境等待工具。不要用sleep/忙轮询，也不反复催用户“是否继续”。

默认最多3个有写入权子任务并行；环境限制更少则降低，环境没有子智能体时由主智能体按同样卡片顺序自己完成，不能伪称已委派。只读审查可独立进行但不可为制造共识反复开agent。使用环境真实可用的subagent/teammate工具，不硬编码不存在的API。若团队成员角色被限制只读，不让它绕过限制写代码，改用允许实现的子智能体或主对话执行。

## 4. 依赖与写入锁

唯一静态DAG见index.json。默认波次：

- W0并行：T00核DSH来源与runtime；T01阶段A只做纯领域契约/fixtures/工具链并交domainReady，不等待T00。
- W1：T00.runtimeReady后T01阶段B绑定实际DSH adapter/root并交runtimeReady；若来源未取得只阻塞该阶段，不阻塞T02等纯领域工作。账户live仍单列，不许把受阻认证当已通过。
- W2：T02存储、T03导入、T04知识、T08界面壳可并行；共享公共文件只由T01 owner变更。
- 后继按具体deps：T05首节（T03,T04）；T06状态（T02）；T07教学（T04,T06）；T09材料UI（T03,T04,T08）；T10地图（T04,T06,T08）；T11图示批改（T03,T04,T06）；T12学习UI（T07,T08,T09,T10,T11）。
- T14全册内容在T05后可与其余功能并行，且接续T05内容目录的写权。T13首节集成依赖T05,T12，不等待全册才发现集成错。
- T15依赖T13,T14，执行全册和教育质量门；T16依赖T15打包；T17独立最终验收依赖T16。

解锁依据是index.json中readinessDependencies指定的阶段门已被接受且实物可用，不是前置全部global AC已PASS。T01.domainReady可独立，T01.runtimeReady等待T00.runtimeReady；T13必须等实际runtimeReady。前置“代码写完但没验”不足。若仅外部live门受阻，可在报告里精确写“接口可消费/运行未验”，主智能体只解除未受该门影响的子项，必须在PROGRESS记录条件/AC，最终验收仍不准PASS。

每卡允许写包目录+自身reports/requests，其他共享文件只读。新依赖申请写requests/Txx.md，主智能体交当前公共配置owner串行安装/锁文件更新，不准一边并行pnpm install一边各改锁。根旧package/旧lock保持不动；新education根配置owner依次T01→T13→T15→T16。runtime组合/路由/注册由T01建骨架、T13串行汇总，各功能给factory而不争抢入口。T08完成后shell组件亦不允许其他UI任务私改，由请求机制或T13集成处理。

Git提交不是必须；若执行用户要求提交/PR/发布，另外遵守相应技能与授权。默认不reset/clean/覆盖用户改动；不为并行自动建多个worktree再让它们用同一运行数据。若环境提供可靠隔离checkout，可以用，但主智能体负责diff集成、依赖同步和最后真实验证。

## 5. 子提示词必须自足

按SUBAGENT-PROMPT填：身份目标、taskId、卡片绝对路径、工作区、已确认用户决策摘要、准确依赖报告/hash、允许/禁止写scope、公共契约版本、必须验证AC、live预算/凭据使用范围、报告路径、失败返工策略。fresh agent不能依赖“见之前聊天”。只给必要资料，但关键契约必须可读。

子智能体不得另开一套产品方向、重写公共schema、扩大功能、擅自发布或用mock冒充live。执行卡内实现后先自测、交回完整报告；遇局部问题可在scope内自主修复。需要跨scope修改发结构化请求，主智能体处理，子智能体继续不受影响部分。未经确认不能同时变更双方接口。

## 6. 接受、返工与对话收尾

每个实现子任务至少交：改动路径、实现摘要、实际命令/退出码、AC结果与证据、未测项、依赖兼容、阻塞范围、后继需要的输入。主智能体抽查diff与关键失败场景，确认没有秘密/原文入库、没有scope越界，再接受；失败交还原owner或收回后指派新owner，禁止同scope双写。

连续同一失败两次不盲目重跑：缩小复现，检查输入/契约/环境；换方法要记录新证据。子智能体崩溃/上下文耗尽时回收产物并区分已写未验；重新启动替代agent不重复做已通过部分，读最新文件避免覆盖。总体不设“做三张卡就结束”的人为上限，但重试不能产生无意义空转。

关键接口/高风险数据路径由不同上下文进行只读复核；审查结论是证据，不以多数票决定正确。主智能体完成集成与全局测试，子任务全绿不等于产品全绿。最终报告与当前代码/内容/产物hash绑定；修改后旧报告不能继续引用为现行通过。

## 7. 真实外部阻塞与提问

尽早核实三类输入：合法DSH固定来源与平台授权、真实教材PDF位置与使用范围、真实模型凭据/图像能力/小额测试预算。只问确实影响执行的缺口，一次集中提出、写清推荐与理由；若有异步提问能力，等待时继续所有独立工作。

不能凭时间推定用户已授权预算/账户/材料。能够通过源码/文档解决的问题自己核实；不得重复问已确认六项产品选择。当全部ready工作都完成而只剩同一外部阻塞时，保留工作、输出blocked报告（缺什么、影响哪些task/AC、已完成什么、输入到位的恢复入口），不宣称目标完成，也不维持无限空转。用户补充后从blocked点恢复，不重开全套需求访谈。

## 8. 唯一正常完成条件

T17对07矩阵逐项PASS且scope目标全满足，主智能体才能标完成。交付：可运行Windows产物、启动/使用说明、全册coverage/来源审校、真实DSH/文本与图像模型证据、三轴状态与恢复记录、权限与包内容扫描、完整交回报告。教育收益研究若没做要明确未做，不阻断软件/内容工程交付，但绝不冒称已证实。

未通过的账户授权、图片批改、全册来源或打包不得用“后续优化”掩盖；如用户明确改变范围，将变更记录为新决策、更新AC和所有受影响卡，再执行，不能由模型自行削减。
## 9. 共享工作区的检查屏障

并行子任务只运行自己的typecheck:task/test:task与只读公共契约检查。全量typecheck/test/build、依赖安装和锁文件更新前，主智能体通知所有活跃写worker在安全点暂停、确认已保存并释放写锁，记录一致代码指纹，再串行运行。检查后分派失败归属；其他worker不得一起修公共报错。受影响consumer在contract变更时暂停并重验，验完再恢复。

失败次数、原因、修复与再次验证写入任务报告和主控进度，替换agent不清零。无活跃worker、无ready工作且剩余全为外部输入依赖时，输出具体blocked交接并等待真实输入；不能把wait无进展当持续工作。
## 10. 阶段门和全局AC分离（防验收循环）

报告分别给gateStatus与globalAcStatus。子模块以卡片exitCriteria在本阶段可实现的L1/L2/L3验证后交implementationAccepted（或指定domainReady/contentReady等），主控可解锁后继；尚需教育UI、真实模型、全册或打包才能产生的全局证据按deferredGlobalAcceptance交T13/T15/T16/T17补验，保持NOT_RUN/BLOCKED，不能提前PASS。T00不要求已有Windows包，T03不要求先完成T16才交导入服务，T04不要求先有后继教材UI。

最终完成仍要求07全部AC在最低等级PASS；阶段门只是依赖就绪，不降低最终标准。index.phaseGates明确T01.domainReady无T00前置，T01.runtimeReady依赖T00.runtimeReady；T13必须runtimeReady。每次调度按gate而非整个前置任务是否“最终全通过”判断，持久记录条件与未来补验owner。
