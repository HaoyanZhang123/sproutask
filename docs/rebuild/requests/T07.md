## R2（F4 根因之一）`G1Service.localRuleTurn` 不能伪造 tutor revision / 绕过 learner

- 现象（T15 证据 `education/.local/evidence/T15/rerun-review5/review-evidence.json`）：模型不可用时的本地规则回退返回 `revision = input.revision + 1`、`state.revision` 同步伪造，但 **tutor 服务内的 session revision 未递增**（真实 session 仍是 0/1）。随后 `finish-review`：
  - revision 0 → 进入 learner 后因无 Assessment 被拒（旧映射显示为 `UNAUTHORIZED: REVIEW_OUTCOME_MISMATCH`）；
  - revision 1–12 → 全部 `STALE_REVISION`（tutor 状态未变）。
- 本次 T07 已让 terminal finish 接受 `revision <= 当前 state.revision`（未来 revision 仍拒），因此 `finish-review` 不再因回退伪造的 revision 卡死；但回退**只把 attempt 写入 storage，没有经 `@edu/learner` 记录 evidence/assessment**，复习完成只能按默认 `needs_support` 落账（见 T06 修复），无法产生基于本次复习证据的 `developing`。
- 请求（T13，二选一，优先 A）：
  - A. 本地规则回退也走同一教学服务：给 `TutorService` 增加一个 local-rule 提交入口（或让 `G1Service` 调用 `learner.submitAttempt` + `recordGradedAttempt`），并把 tutor session revision 与回退结果一致递增；这样 `finish-review` 后 review outcome 可由本次证据推导。
  - B. 至少不要返回与 tutor 状态不一致的 revision：回退响应沿用 `tutor.getState(sessionId).revision`，并明确 `gateway:'local'`；否则客户端无法知道该用哪个 revision。
- 验收：`start(review) → 一次回退 turn → finish-review(outcome=developing)` 返回 ok 且 review.latestOutcome=developing；若没有证据，则只允许 needs_support。

- 客户端请使用**最近一次真实 tutor 回合返回的 `outcome.revision`/`state.revision`**；terminal finish 现在也接受更旧的 revision（含 0）以防回退/重试，`revision > 当前` 仍返回 STALE_REVISION。

## R4（A20 接线）图片路由传入可解码像素与声明尺寸

- `evaluateImageAnswer()` 现在在调用视觉模型前先做独立质量判定，需要 `requestImage.base64` 是 **完整 PNG** 且 `width/height` 与 PNG 一致；不一致/非 PNG 会返回 `qualitySignal.status='unavailable'` 且不强制澄清（不猜测）。
- 请求：
  - host 图片上传路径继续传 `base64 + mime + width + height`（不要只传 assetId 或截断 base64）；
  - 若上传是 JPEG/WebP，请在 host 侧转成 PNG（或在 T11 扩展解码器）；否则独立质量闸门不生效；
  - 被强制澄清时 `grade` 非 null、`requiresClarification=true`、`uncertainties` 含 `quality_signal:` 与 `threshold_version:image-quality-v1`；UI 应展示澄清文案与 retake/text 动作，不要当答错。
- 验收（无需模型）：对 T11 `03-rotated-blurred.png` 走产品图片路由应返回 clarification；`01/02/04` 不应被误杀。
