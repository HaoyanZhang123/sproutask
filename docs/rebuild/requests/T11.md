## R3. T12/T13 消费接口

- `@edu/visuals`（服务层）：
  - `validateControlledDiagram(spec)` → 受控 DiagramSpec；`planDiagram(spec)` → 确定性布局；`renderDiagramSvg(plan, opts)` → 无脚本静态 SVG（含 `<title>/<desc>`）。
  - `gradeAttempt(context)` → `GradeResult`（diagram_label / choice / relation / text 四种规则评分；`graderVersion` 分别 `rule-*-v1`）。
  - `gateEvidenceCandidates({grade, activity, rubric, attempt, resolveSourceRef, knownConceptIds})` → 仅接受通过校验的证据候选，拒绝项带 code + audit；`submitAcceptedEvidence({decision, activity, sink})` 交给 learner 端口。
  - `evaluateImageAnswer(input)` → `{stage: graded|clarification_required|degraded_text, grade, gate, clarification, recognition, provenance, injection, quality}`；`ImageAnswerSession` 管理 preview→confirm→recognize→revise→grade 状态，修订会把旧评价移入 `supersededEvaluations`。
  - `detectImageCapability(capability)`、`scanForPromptInjection(text)`、`assessRecognitionQuality(...)`、`createDeepSeekVisionClient({apiKey, model, ...})`、`buildVisualsEngineStatus()`。
- `@edu/client-visuals`（DOM 层，无框架）：
  - `mountDiagramView(container, {spec, plan, onSubmit})`（图上点选与编号输入等价）
  - `mountAnswerForm(container, {activity, relationNodes, onSubmit})`（choice/text/relation；diagram 由 diagram view 负责）
  - `mountImageFlow(container, {flow, onPreview, onConfirmSend, onRevise, onClarificationAction, onTextFallback, onCancel})`
  - `mountFeedbackView(container, {grade, sourceLabel, onOpenSource, onClarificationAction, injectionNotice, candidateOnly})`
  - `createSlotPanel(id, controller)` / `registerVisualsPanels(registry, {visuals, feedback})` → 挂到 T08 壳的 `study:visuals` / `study:feedback`。
- 需要主控/集成方提供（不在 T11 scope）：
  1. `LearnerEvidencePort` 的真实实现（把 accepted 候选交给 `@edu/learner`，T13 接线）；
  2. `resolveSourceRef`（书库/知识服务）与 `knownRelations`（`@edu/knowledge` 的 Relations）；
  3. 运行时 image capability（`runtime.capabilities.model.image`）与宿主密钥存储；`@edu/visuals` 不读取秘密文件。
