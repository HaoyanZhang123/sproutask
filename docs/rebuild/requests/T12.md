# T12 变更请求与后继输入

## 1. T13 真实接线（必须）

`@edu/client-study` 只消费注入的 `StudyDataSource`，不 import tutor/learner/importer 的实现文件。T13 需要实现同形状 facade：

- `startSession/submitTurn/skip/end/finishLearning/finishReview/retryPendingGrading` 委托真实 `TutorService`（T07）；`StudyTurnOutcome` 是 `TutorTurnOutcome` 的结构子集，实际字段可直接返回。
- `loadWorkspace/loadProgress/loadReviewRange/deferReview/saveSelfReport` 由 `KnowledgeService`（概念/活动/出处）+ `LearnerService`（三轴/复习队列/自评）适配；`deferReview` 必须委托 T06 的 review policy，不由 UI 改 dueAt。
- `loadDraft/saveDraft/clearDraft` 接本机持久化（T02 journal/独立 draft 记录由 T13 决定）；提交成功后清草稿，草稿不冒充已提交作答。
- `submitImageAnswer` 接 T11 图片管线；真实视觉能力/不确定项由 T11/T13 返回，UI 不自行判懂图。
- `createRequest` 使用组合根真实 `RequestContext`；`returnPath` 由 T12/T13 传入，用于查看出处/返回原活动。

## 2. 教学语义

- `submitTurn` 的 `attempt.answerText` 对 choice/relation/diagram 使用 `src/labels.ts:encodeAnswer` 的 JSON 传输格式；T13 的 `GradePort` 必须按 `activity.answerSchema.kind` 解码（或换成等价的显式字段约定）。这一点需要在 T13 接线时固定，UI 不自行改评分。
- `decision.disclosure` / `helpKinds` 必须来自 T07；UI 只显示中文 assistance/disclosure 说明，不用界面状态替服务决定独立性。
- `finishLearning/finishReview` 的实际完成/理解状态由 T06/T07 返回；T12 只重新读取 `loadProgress` 展示，不本地升级 completed/supported。
- “提交前保存原答”由 T07 的两阶段 pipeline 保证；UI 的 `submitted → grading` 只是显示阶段，不把等待反馈当已保存/已完成。
