# T02 变更请求

结论：不需要新增第三方依赖，也未修改公共契约。以下为需要主控在配置写域执行的串行动作。

## 需要主控执行（非 T02 写域）

1. 运行 `pnpm --dir education install`（把新建的 `education/packages/storage` 作为 workspace 包链接并更新 `education/pnpm-lock.yaml`）。T02 按要求未运行 install、未改锁文件。
2. 运行 `pnpm --dir education contract:lock:generate` 重新生成 `docs/rebuild/contract-lock.json`。T02 新增了 `education/packages/storage/**` 文件，旧 lock 的 124 文件 hash 立即过期；T02 未修改该文件。
3. 然后运行全局 `pnpm --dir education typecheck` / `test:contracts`（`test:contracts` 会先校验 lock，再运行 storage 的 contract test）。

## 说明 / 潜在增量

- `@edu/storage` 的 runtimeDependencies 为空，仅使用 Node 内置 `node:fs`/`node:path`/`node:crypto`；测试使用 `node:os` 临时目录。无 license 新增项。
- 组合根接入建议：`createStorageFeature({ root, clock, ids })` 返回 `{ storage, eventStore, featureModule }`；用 `eventStore` 构造 `createEducationComposition({ eventStore, ... })`，再把 `featureModule` 传给 `FeatureRegistry.register`。factory 会在注册时校验 `services.eventStore` 是同一个实例，不修改只读 services。
- 若后续要求把 `@edu/storage` 变成 DSH runtime 的正式包入口，需要主控决定 runtime 包的提升方式（T01 时 runtime 不是 workspace 成员）；当前 storage 不依赖 runtime，保持 domain←storage 方向。
- 旧数据迁移仅支持本包实现的通用 JSONL 记录（`learnerId` + `mastered`/`exploring`/`state`）；如旧 S00 的实际 schema 与此不同，需要 T17/主控提供样本后追加映射，不会自动扫描或改写旧数据。
