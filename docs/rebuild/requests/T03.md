## R1. 新 workspace 包 `education/packages/importer`（锁文件是否刷新，由配置 owner 决定）

- 新增：`education/packages/importer/package.json`（`name: @edu/importer`，`type: module`，`private: true`，**未声明任何依赖**），`tsconfig.json`，`vitest.config.ts`。
- 已实测（在 `.local/cache/T03/lockcheck/` 的隔离副本里，未在真实工作区执行 install）：
  - 该空 manifest 加入 workspace 后，`pnpm install --frozen-lockfile --lockfile-only` **仍通过（exit 0）**，因为 pnpm 对空 importer 不写入 `importers` 条目；
  - 若在该 manifest 里声明 `"@edu/domain": "workspace:*"`，则同一命令 **失败**（`ERR_PNPM_OUTDATED_LOCKFILE`，exit 1）。
- 因此 T03 选择“manifest 零依赖”以保证主控现有 `--frozen-lockfile` 门不被打破；`@edu/domain` 通过根 `education/node_modules/@edu/domain` 链接解析（已由 tsc / vitest / 直接 `node` 运行三种路径实测）。
- 请配置 owner 二选一（推荐 A）：
  - **A（推荐）**：运行 `pnpm --dir education install` 重新生成 `pnpm-lock.yaml`（会把 `packages/importer: {}` 写入 importers），并在 importer manifest 里加 `"@edu/domain": "workspace:*"`，再复跑 `--frozen-lockfile` 与 `contract:lock:verify`。T03 未改锁文件，也未执行 install。
  - **B**：保持现状（空依赖），由根依赖提供 `@edu/domain`，不刷新锁文件。
- 影响：`docs/rebuild/contract-lock.json` 的“124 文件/命令”清单是否要纳入新包，由契约 owner 决定；T03 未改该文件。

## R2. T16 打包必须包含的物料（已在 `src/materials.ts` 机器可读化）

1. `education/packages/importer/src/engines/scripts/winrt-ocr.ps1` 必须随包发布（T16 的 asar/files 白名单），脚本为纯 ASCII，无秘密。
2. 目标机需要 Windows 10 1809+ 的 `Windows.Data.Pdf`、`Windows.Media.Ocr` 与 **中文(简体) OCR 语言包**（`Language.OCR~~~zh-Hans-CN`，系统可选功能，非可再分发）；缺失时导入会以 `OCR_LANGUAGE_UNAVAILABLE` 明确暂停/失败，而不是静默出空文本。
3. 需要 `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`（标准 Windows PowerShell 5.1 即可；本机无 PowerShell 7，脚本按 5.1 兼容编写）。
4. **不依赖** Tesseract / Ghostscript / Poppler / Python，不需要开发机 PATH；A05 的 L5 证据需 T16 在“无开发 PATH”的打包产物上复验（本卡只到 L2）。
5. T16 应把 `importer.engineStatus()`（`EngineStatus.materials`）接到安装自检/诊断页，便于用户自助定位语言包缺失。
