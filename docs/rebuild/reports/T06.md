1. **三轴投影（纯事件折叠）**：`src/projection.ts` 的 `LearnerProjector` 从 journal command 折叠出 `ConceptProgress`。`learning`（not_started/in_progress/completed + startedAt/lastCompletedAt）只由 `session.started(learn)`、`learning.completed` 变化；`understanding` 只由 `assessment.committed` 与显式 `evidence.staled` 变化；`review` 由 `learning.completed`（首复习）、`review.completed`、`review.deferred` 独立维护 `lastCompletedAt/dueAt/activeSessionId/latestOutcome/policyVersion`；`lastPosition` 由 session/attempt 更新。`SelfReport` 走独立 `self_report.recorded` 事件与内存列表，**不写 ConceptProgress、不产生 Assessment**。诊断 session 不创建学习投影；取消/跳过只结束 session/cancel grading，不判错、不伪造 completed。

## § 复核返工 2026-10-30（F4：复习完成落账）

### 原缺陷

`LearnerService.completeReview` 在无当前 Assessment 时直接拒绝（`REVIEW_OUTCOME_MISMATCH`）。candidate 内容包按 05 §3/§9 必须保持 `understanding=unassessed`，因此真实复习会话**永远无法完成**；T15 产品路径的 `finish-review` 因此卡死（详见 `docs/rebuild/reports/T07.md` 的 F4 节与 `docs/rebuild/requests/T07.md`）。同时旧错误映射把它显示成 `UNAUTHORIZED`，误导为权限问题。

### 修复后的复习完成语义（论文般明确，不冒充掌握）

- 会话必须 `active`；abandoned/completed → `CONTRACT_REJECTED: REVIEW_SESSION_NOT_ACTIVE`（revocation 场景）。
- **有 Assessment**：显式 `outcome` 必须与最新 Assessment 一致（原 M-04 防越权语义保留）。
- **无 Assessment**（candidate / evidence-only）：
  - `needs_support` 允许落账，仅写 `review.latestOutcome/lastCompletedAt/dueAt`，**不写 understanding**；这是“复习完成·仍需巩固”，不是掌握声明。
  - `developing` 需要**本复习会话绑定**的当前证据（attempt.sessionId 匹配），且不得有 core misconception/全部 not_met 反证。
  - `supported` 始终拒绝（必须 Assessment；复习活动不能升级理解）。
- `requestId` 幂等：重复同一 completeReview 返回首次结果（duplicate=true），不重复追加 review 完成事件。
