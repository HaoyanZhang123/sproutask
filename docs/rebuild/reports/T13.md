## F1/F2/F3 根因与修复

### F1（阻断，已修）：DSH turn 没有 assistant 文本

根因有两层，均在 `runtime/src/adapters/dsh-tutor.ts`：

1. `handle.agent.followup()` 只传了 `{content,source}`，没有 DSH `UserMessage` 必需的 `role:'user'` 和 `id`。DSH 会话因此产生 role=`null` 的畸形 user 消息，模型回合不能正常收尾，`deriveMessages()` 只有 `[system, null, user]`，没有 `assistant`。
2. adapter 在 idle 后从 `ctx.sessions.get(sessionId)` 读消息，而不是读取 `handle.agent.session`（agent 自己驱动的权威 session）；即使 assistant 已提交，也可能读错对象。

修复：followup 显式 `{role:'user', id:'msg-…', content, source}`；idle 后优先 `handle.agent.session.deriveMessages()`；debug 记录完整 roles。修复后同路径 roles 出现 `assistant/tool/...`，`/g1/tutor/turn` 返回 `ok:true`。

### F2（高，已修）：教学 Skill 指令没有下发

`@edu/domain` 的 `TutorTurnRequest.systemInstruction` 现由 T07 `gateway-adapter` 传入；`dsh-tutor.ts` 在 session 打开时通过 agent 的 scoped `systemPrompt.section` 注册动态 section `edu:teaching-skill:<sessionId>`（order 100、`interpolate:false`、文本闭包），每个 turn 把 `request.systemInstruction` 写入该 section。debug 记录 `dsh.system-instruction chars=1185`，与 T15 报告中的 Skill 指令长度一致。模型侧已按教学策略回答（先探问、再纠错/解释、disclosure 标记）。

### F3（高，已修）：教育工具返回值不足以让模型定位 concept/SourceRef

### F5 (high, fixed): the first "start learning" after a restart failed with a TypeError

**Symptom (T15, reproducible)**: after a product restart the first `POST /edu/api/g1/tutor/start` returned `UNAVAILABLE: model request failed: Cannot read properties of undefined (reading 'length')` with **0 model calls**; retrying with the next session id worked.

**Root cause (confirmed in code + T15 evidence)**:
- `education/packages/tutor/src/tutor-service.ts` allocated `id: request.sessionId ?? ids.next('session')`, and `createSequentialIdGenerator` is a per-process counter (`session.1`, `session.2`, …).
- DSH persists every session under `<DSH_HOME>/sessions/<cwd>/session.N` (T15 store: `session.{2,3,4,14,21}`). After a restart the counter begins again, so the first minted id can name an already persisted session.
- `ctx.agents.create({sessionId})` then takes the restore path and throws `TypeError: Cannot read properties of undefined (reading 'length')` before any model request. `runtime/src/adapters/dsh-tutor.ts` only handled the `already exists` message and re-threw this TypeError.

**Fix (no reliance on "retry the next id")**:
1. New `education/runtime/src/adapters/session-ids.ts` — `createDshSessionIdGenerator` keeps the opaque `session.N` shape but **skips every id already present in the DSH session store** (recursive scan of `<DSH_HOME>/sessions/**`, depth 3, directories and flat files), reserves ids handed out in this process, and falls back to a timestamp+random suffix if the store cannot be read or is exhausted.
2. `education/runtime/src/runtime-composition.ts` — resolves `DSH_HOME` (`options.dshHome` → env `DSH_HOME` → `<dataRoot>/../dsh-home`) and wires the store-aware generator as the production default; `ids` stays injectable for tests. Exported as `resolveDshHome`.
3. `education/runtime/src/adapters/dsh-tutor.ts` — a TypeError from `agents.create`/`agents.resume` (in both `open()` and `resumeSession()`) is converted to the structured service error `UNAVAILABLE / SESSION_RESUME_FAILED`; the raw TypeError text goes only to the debug audit (`dsh.session.create-failed` / `dsh.session.resume-failed`), never to the student/service message.
4. `education/packages/tutor/src/tutor-service.ts` — safety net: if the first bind fails with `SESSION_RESUME_FAILED`/the restore TypeError and the caller did not pin a `sessionId`, allocate the next store-aware id and retry **exactly once** (audit kind `session.retry`). Start only binds the DSH agent, so the retry is still **0 model calls**.

**Regression tests (offline, fake DSH agents — binding only, no model)**:
- `education/runtime/test/session-id-collision.test.ts` (5 tests): with `<dsh-home>/sessions/_no-cwd/session.3` on disk and the counter at 3, the next session id is `session.4`/`session.5` (never `session.3`); a real `composeEducationRuntime` start succeeds and `agents.create` receives exactly the new id; the retry path records `['session.3','session.4']` and binds `session.4` with `turnCount=0`; a persistent collision surfaces `UNAVAILABLE / SESSION_RESUME_FAILED` (no raw TypeError text, `session.retry` audited).
