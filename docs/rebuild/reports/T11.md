## 失败与返工

2. **选择/关系/文字测试首轮 3 失败**：① 缺答案键提示文案与断言不一致（改为“内容包缺少答案键（correctOptionIds）”）；② 关系“未知类型”用例的 activity 与 rubric id/version 不匹配（按契约返回 `RUBRIC_MISMATCH`，修正 fixture 而非放宽断言）；③ 文字误解检测误把 bigram 集合当原文，导致“看见过就等于观察过”未命中（改为在归一化原文上做子串匹配）。
3. **客户端测试首轮失败**：`setAnswer` 只写给定字段，残留上一次输入导致答案多一项；改为“替换即清空后再写入”，语义更明确。

5. **真实调用首轮策略问题**：空白样本首版落到“模型没有给出可判断的比较结果”，提示不如“图片里几乎没有可识别的内容”具体；修正后**重跑 4 次**（前 4 次记为丢弃运行，费用如实计入）。

## § 复核返工 2026-10-30（A20：独立于模型的图像质量闸门）

### 原缺陷

T15 产品路径发现：**旋转 14° + 模糊 6×** 的上传图仍被视觉模型“自信判对”，旧 `assessRecognitionQuality` 完全依赖模型返回的 `readable/uncertainty`，模型说清楚就通过；没有任何独立的像素级质量检查。结果是对不可辨认图片产生错误对错判断（07 A20 阻断项风险）。

### 修复

- 新增 `packages/visuals/src/image/quality-probe.ts`：在**调用视觉模型之前**计算可解释指标：
  - 灰度 Laplacian 方差（模糊/对焦）；边缘密度；强度方差（空白/均匀）；梯度方向直方图的主方向与 `orientationPeakShare`（倾斜）；长宽比。
  - 阈值版本 **`image-quality-v1`**（产品启发式，非视觉科学结论）：`blurLapVar=80`、`tiltDegrees=5`、`tiltPeakShare=0.18`、`uniformIntensityVariance=20`。
  - PNG（8-bit、非隔行、灰度/RGB/RGBA）解码使用 Node 内置 `zlib`；其他格式返回 `unavailable`，**不猜测、不强制澄清**。
- `evaluateImageAnswer` 在 capability 检查后立即执行该闸门；命中时：
  - 直接返回 `stage='clarification_required'`，**不调用模型**（测试用一个“被调用即抛错”的 client 证明）；
  - 文案固定包含 **“图片较模糊/倾斜，请重拍或改用文字描述”**，动作 `retake/text_fallback/edit_text`；
  - 返回非空 `GradeResult`：`requiresClarification=true`、`evidenceCandidates=[]`、`uncertainties` 含 `quality_signal:<metrics JSON>` 与 `threshold_version:image-quality-v1`、`graderVersion=image-quality-image-quality-v1`；**不判错、不产证据**。
- 正常判分路径：`GradeResult.uncertainties` 追加 `quality_signal:<metrics JSON>` 与阈值版本，`graderVersion=vision-image-eval-v1+image-quality-v1`；`ImageEvaluation.qualitySignal` 始终返回结构化信号（degraded_text 除外为空）。
- 领域契约限制：冻结的 `GradeResult` 没有 `qualitySignal` 字段（新增字段需 T01 变更）；因此 threshold/version 与指标 JSON 记录在 `uncertainties` + `graderVersion`，同时以 `ImageEvaluation.qualitySignal` 提供结构化对象——两者都可追溯，未私改 domain。
