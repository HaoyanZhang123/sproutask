## 实现与范围

新增 `@edu/client-library`（`education/client/library/`，无 React/Vue，runtime dependencies 为空）：

1. **教材库三态**：`LibraryBook.materialState = baseline/candidate/unavailable` 分别显示“本期匹配基准 / 待核实候选 / 不可用材料”，并分别渲染书名、出版社、版次、页数、SHA-256 摘要、内容范围（partial 明确“未达全册”）、审校状态、信任模式、版本核实和文件状态。候选卡片持续显示“候选 · 未核实 · 不可作为基准或强掌握结论”；不可用材料显示原因。全部 fixture 页面有“演示数据（fixture）”块和 `data-edu-fixture` 标识。
2. **显式候选试用**：点击“显式试用候选（未核实）”先打开带影响说明和勾选确认的对话框；确认后设置 `candidateTrialBookId`、打开候选来源并持续显示顶部“候选试用（未核实）· 强结论已禁用”；`reviewState`/`materialState` 不被 UI 改写。未试用前不提供候选来源入口；可随时退出试用。
3. **文件选择与元数据确认**：通过 `LibraryDataSource.chooseFile` 获取宿主 `ManagedFileHandle`；显示文件名、大小、检测页数和指纹摘要；元数据表单（书名/出版社/版次/页数）可编辑，确认“只用于匹配，不会变成基准”；页数与文件不一致由服务拒绝并显示结构化错误。没有直接用 `<input type=file>` 读取任意路径。
4. **导入进度与生命周期**：消费 `ImportJob` 的 `stage/status/completedUnits/totalUnits/error/retryable/parserVersion/updatedAt`；阶段条按 `accepted→identify→extract→structure→concepts→validate→await_review→ready` 显示，当前阶段 `aria-current=step`；`progressSummary` 只显示真实页数，不伪造进度。`await_review` 明确“待审核：不是导入完成”，不出现“材料就绪”；`ready` 只按包声明范围显示“材料就绪（按包声明的范围）”。提供取消、恢复、重试失败阶段、刷新状态、重新选择文件；取消后 UI reducer 拒绝迟到/倒退更新。
5. **同 hash/同版匹配提示**：`ImportStartOutcome.reused` 显示“同一文件已存在：复用任务，不会重复建书”；`same_edition_rescan` 显示“同版不同扫描：需要页码映射，当前按候选处理”；`different_edition/unknown` 显示“未匹配已核实版本，生成待核实候选”。UI 不自行判定基准。
6. **失败与离线**：覆盖 `PDF_CORRUPT`、`PDF_ENCRYPTED`、`PDF_NO_PAGES`、`OCR_ENGINE_UNAVAILABLE`、`OCR_LANGUAGE_UNAVAILABLE`、`STORAGE_FULL`、`STORAGE_WRITE_FAILED`、`CLOUD_EXTRACTION_PAUSED`、`CLOUD_AUTH_FAILED`、`CLOUD_RATE_LIMITED`、`ASSET_*`、`CHECKPOINT_*` 等 T03 稳定错误码的中文标题/影响/下一步；离线时显示“在线概念抽取暂缓/本地解析完成/不伪装完成”；错误不显示原始 message、堆栈或路径。
