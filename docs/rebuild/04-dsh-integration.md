# 04 DSH 接入：T00 准入与 T01 接口冻结

状态：方案与交接要求，**尚未实施**。本轮授权仅文档；以下运行、安装、构建和调用模型均为将来用户明确要求实施后的任务。默认不修改现有 DSH 安装包、不替换当前 GUI、不改变旧应用数据。

## 方案边界

目标为 Windows 个人学生桌面，领域架构支持多学科，首期交付人教 2024 七上生物全册概念学习。教学引导优先，允许在适当阶段讲解；不能机械沿用旧版“永不直接给答案”作为新硬规则。新代码隔离于当前不存在的 education/；本轮不创建实现骨架。旧工作区只作证据与参考，迁移必须显式转换，禁止直接读取为新事件真相。

教育层拥有教材目录与来源、概念图、学习证据、复习策略、教学会话、事件日志和学生界面；DSH 仅通过适配器提供 Agent 循环、模型路由、受限工具、附件及必要 Host/Client 连接。领域代码不得依赖 DSH、Electron、React/Vue 的运行时类型。DSH 依赖集中在适配器/组合层，便于替换版本或运行时。

**责任**：运行时集成负责人。输入为 [静态证据](<E:/DSH/workspaces/ai4edu/docs/rebuild/03-evidence.md>)。当前安装版仅是线索，不能作为将来构建输入或从用户安装目录偷偷取依赖。

| 5 模型与账户 | 分开验证已有账户授权和 API Key；只用获准测试凭据，不写入文档/日志；核对模型目录、错误与额度路径 | 可用路线、服务端准入依据、版本能力与错误矩阵；费用调用范围 | 平台许可未知时保留“待确认”，不能演示绕过或抓 Cookie |

**认证判定必须细分三层**：

1. DeepSeek 账户/Key 是模型消费身份。随包实现使用开放平台的 DSH 专用 PKCE 流程，不是通用“用 DeepSeek 登录任意应用”的已证明能力。第三方教育产品准入、应用注册要求、品牌和使用许可由 T00 核实，不能凭源码 MIT 推断。
2. Host 连接认证保护本地 API/流访问，与模型凭据不同。保留 token-cookie 或所选载体等效认证、Host/Origin 检查、参数与资源授权；原生载体若替换，须验证等效边界。
3. 学习身份是本地 learnerId 与教育日志归属。不能用 DeepSeek 账号 ID 代替 learnerId，切换模型账号不迁移/覆盖学情，登出模型不删除学习记录；删除本地学习数据与模型退登分别处理。首期个人桌面不承诺多学生/学校多租户隔离。

已有账户授权和 API Key 为**独立路线**：账号 token 使用 x-dsh-auth-token，Key 使用 x-api-key，不静默回退。API Key 也需要明确的服务可用性、存储与分发约束验证；不把“改用 Key”写成已通过的兜底。学习体验可先支持一条通过的文本模型路线，不能因此宣称账户路线已获准。平台现有回调限本机显式端口/SSH 转发，无 token 过期刷新流程的文档限制须验证适配，不自行虚构刷新协议。

## root 替换与宿主边界

已核实 [根渲染契约:32](<E:/DSH-desktop/resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-client-ui-renderer/README.zh.md#L32>) 允许根占用方拥有产品布局与 document 元数据；[默认布局:30](<E:/DSH-desktop/resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-client-ui-layout/README.zh.md#L30>) 本身为客户端插件。因此材料、概念图、练习与复习界面可采用教育客户端 root 替换默认布局，不能笼统要求 fork 整个宿主。**这是静态可行性，不是装载成功证据**。

T00 须证明停用默认 root 后无重复占用、教育 root 正确挂载、依赖服务可用、错误可恢复；若复用已有组件，须维护其 slot、上下文和服务契约。独立 root 不能继续假定默认 sidebar/main/rightbar 已被声明。客户端插件需要构建后的 bundle 与 dsh.client 元数据。

普通页面插件边界之外包括原生 Electron 窗口、preload/IPC 信任面、安装更新、启动内核/静态 seed 模块。将来若必须更改这些，先记录具体需求与影响，另立宿主变更，不默认纳入“纯插件”。T16 才验证 Windows 包装、冷启动、卸载/升级与数据保留；本机现有安装不算该验证。

登录页和高级设置页可以重做或移出学生主界面；Host 后端的认证、密钥隔离、工具守卫与配置校验不得因 UI 简化而消失。学生不能通过直接 RPC 或模型工具恢复被隐藏的开发者能力。

## T01：新工作区骨架与公共契约冻结

**责任**：教育架构负责人。T01阶段A domainReady可与T00并行，实现并验证纯领域契约/fixtures/工具链，解锁不依DSH的模块；阶段B runtimeReady才依赖T00.runtimeReady并绑定真实DSH接口。阶段接受与最终AC分离，不能因T00来源缺失锁死纯领域工作，也不能用domainReady冒充已接入DSH。

未来 education/ 按[系统设计](06-system-design.md)的目录和owner表落实职责隔离；必要适配差异须走[执行交接](08-execution.md)的契约变更，不由每个任务自行选目录；不复制旧工程。协议有显式 schemaVersion，Host 对所有不可信输入校验，客户端仅收安全 DTO。以下为**待冻结契约要求**，名称可在 T01统一调整，不能声称本轮已实现。

| 契约 | 必须冻结的内容 | 必须证明的边界 |
|---|---|---|
| 学习身份与空间 | learnerId、学习会话/学科/册次/章节标识、数据根目录归属；模型账户引用另存 | 更换模型账号不换学情；无真实姓名强制项；首次启动与空数据可用 |
| ContentSource / Citation | 本地 PDF sourceId、原文件指纹、版本信息；PDF 页索引与印刷页区分、章节/块定位、提取/OCR provenance；缺失/未校对状态 | 不用文件名当稳定身份；不可将 OCR 页号与印刷页混用；原文不分发 |
| OrderedEvent / EventStore | 事件 schemaVersion、eventId、流标识、单流递增 sequence、occurredAt、causation/idempotency 信息、payload 校验与 append 确认语义 | JSONL 有序追加是学习事实真相，时间戳不决定顺序；UI/模型不直接改日志；明确单写者、并发冲突、重复、坏尾行与中段损坏策略 |
| ReadSnapshot / Query | lastSequence、投影版本、可重建状态；只读查询与更新事件命令分离 | 快照不是第二写入真相；丢弃后重放可重建；DSH 会话存储不等于教育学习日志 |
| Tutor / LearningCommand | 引导/解释策略输入、内容证据、学习意图与上下文、取消/超时、流式事件、最终状态；三轴状态/学习证据/复习视图的公共字段 | 模型只建议，应用服务校验并提交事实；参与行为不自动等于掌握；解释允许但需出处和教学策略 |
| ModelGateway / Capability | provider/model、text/image 等实际能力、鉴权方式引用、限额与费用信息可用性、结构化 AUTH/QUOTA/UNSUPPORTED/NETWORK/CANCELLED 等错误 | 不以模型名称猜图片能力；不暴露 token；无图像能力时禁用相应操作并说明，可走文本链路 |
| Attachment / ImageAssessment | 不可变附件引用、摘要、像素/旋转/裁剪等变换 provenance、原图与请求图映射；批改结果、置信不足/无法判断状态 | 模型输出不覆盖原图、不凭空补写答案；真模型验收前图片批改保持未通过 |
| DSH Adapter / Remote DTO | 工具定义、入参/出参、允许清单、查询与命令、scope、取消、幂等键、访问权限与生命周期 | 教育领域不 import DSH；工具和 UI 调同一应用服务；客户端或模型不能绕过验证；Skill 只做编排与教学指引 |

T01 应交付接口说明、可执行且冻结的类型/schema、事件/错误样例、依赖方向与迁移政策，以及后续任务可执行的契约验收表。接口验证至少涵盖成功、非法输入、取消、重复提交、缺失材料、无凭据/额度不足、无图像能力和旧 schema 不兼容；不得编造已通过测试。T02 负责日志实现及崩溃/重放验证，T06 负责三轴状态/证据/复习规则，不在 T01 提前声称已实现。

## T03：PDF 接口与材料准入

T03 先用自有/获准 fixture 覆盖文本 PDF、扫描页、混排图表、旋转/多栏和损坏文件。冻结提取结果、OCR 来源、页码映射、章节定位、原图裁剪坐标、失败与重试状态；保持原 PDF 不可变，衍生物可重建。选择解析/OCR 引擎时记版本、许可证和 Windows 分发成本，T16 复核二进制。

当前工作区无实际教材 PDF，现有旧一节文本不是全册材料。T05 首节和 T14 全册真实内容验收须取得并核实实际教材封面、版权页、版次、目录与页数，并进行必要来源对照核查；检查者为AI或人工须如实登记，AI不得冒称人类专家；自有 fixture 通过只能证明机制，不能替代内容验收。PDF 原文及受限衍生材料仅本地存储，索引和自写概念内容与版权原文分开。上云只传当前任务必要内容，并向使用者准确说明该数据边界。

## T11：图片与图示验收，不能与 harness 混同

[模型适配器:1438](<E:/DSH-desktop/resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-llm-deepseek/lib/index.js#L1438>) 检查 image 能力与附件服务；[通用附件:40](<E:/DSH-desktop/resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-attachment/README.zh.md#L40>) 仅把非图片文件投影为路径句柄。因此“支持上传”“可预览 PDF”“有 Skill”均不能作为识图/OCR/批改效果证据。

T11 必须使用通过准入的真实模型与代表样本，记录模型/版本/提供方、图片请求尺寸与变换、必要请求内容、结果、误判/无法判断及费用/耗时；不记录凭据。验收样本应覆盖清晰/模糊、旋转、手写、图表、空白/多解和含无关个人信息等失败条件。由教学负责人预先定义可核对答案、误判容忍与需要人工复核的范围，不能事后只挑成功图。禁止以 mock、目录声明或截图正常代替真模型验证。未通过时不开放图片批改，仍可提供已通过的文本学习功能。
