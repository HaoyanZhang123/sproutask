# 工作包交回与最终报告模板

> 后续主控/子智能体使用。报告是证据，不是另一套全局进度。当前不创建虚假已完成任务报告。

## 1. 工作包报告

~~~markdown
# Txx — 任务标题
- 报告结论：待主控接受 / PASS / PARTIAL / FAIL / BLOCKED
- 当前代码版本：commit + dirty文件摘要/hash；工作目录；日期时间/时区
- 依赖报告及指纹：列真实路径和接受记录
- 内容/契约/DSH/model版本：不适用明确标注
- 任务重试：累计次数、同一失败次数、换agent记录

## 实现与范围
实际做了什么；改动路径；未改动/保留的既有用户变更；scope是否越界及主控授权记录。

## 验收结果
| AC | PASS/FAIL/BLOCKED/NOT_RUN | 证据等级 | 操作/命令 | 输入fixture/真实材料 | 结果/退出码 | 本地证据路径和hash |
|---|---|---|---|---|---|---|
逐项列本卡AC；不能用单句“全部通过”。历史报告不是本次结果，未跑不能写PASS。

## 运行记录
每条实际命令、开始结束时间、环境、退出码、完整日志local位置；需要背景job的ID和最终状态；mock/live明确区分。

## 失败与返工
原失败/复现、原因、修复、验证；旧失败证据保留。没修的问题写影响task/AC和建议owner。

## 数据/安全/许可
是否发送云端、范围/模型、获准预算/实际费用或未知、原文图/秘密排除、依赖license、测试是否隔离旧数据。

## 接口与后继
契约版本、注册factory/公开API、破坏兼容变更请求、后继调用步骤、输入缺口、重启恢复方法。

## 下一步/需要主控的请求
可以继续的工作；真正外部阻塞及所需最小输入；不得用“请确认是否继续”代替具体缺口。
~~~

原PDF/裁图/OCR全文/真实回答和详细云端交互只存education/.local/evidence/<task>/<run>/，不把它们粘到可提交报告。Git报告只留匿名摘要、版本/hash与本机路径；路径跨机器依赖需说明，秘密永不留明文。清晰区分机器自动检查、AI来源对照、真实人工核查，不能称AI为教师专家。

## 2. 主控接受记录

主控在[工程进度](../PROGRESS.md)重构区记录task、owner、报告、当前指纹、核查项目、AC结果及接受/返工理由。若报告中的AC涉及尚未达到的最低证据等级，不能接受该AC，允许其他独立代码接口先被条件消费但需明确条件。

## 3. FINAL-REPORT最低内容

- 目标与决策版本、实际交付范围，有无用户明确范围变化。
- 18工作包结果；R01–R18与A01–A36当前矩阵。
- 用户如何安装、登录/配置、导入、查看地图、学习、复习、看反馈和继续上次。
- DSH固定来源/构建/插件、实际会话与教育工具证据；账户准入与Key分别结论。
- 真实教材版本/hash、全册目录及概念分母、逐项来源审校与人/AI角色，不能只首节。
- 实际Windows产物路径/hash、安装卸载和隔离数据验证、OCR无开发PATH验证。
- 本地/云端边界、工具拒绝、来源与秘密包排除、license/NOTICE。
- 性能/可访问性、失败/取消/重试/损坏恢复结果。
- 未做教育实证与真实局限、BLOCKED或FAIL不得计作完成，输入到位恢复步骤。

这份报告交回原主对话时无需贴全部日志，保留链接与可核查指纹；主控仍需总结最重要结果，不只说“请看文件”。
