# ADR-0005：公开发布范围与许可

- **状态**：**Accepted（2026-09 拍板）**
- **日期**：2026-09
- **影响**：发布流程（`publish/`）、README 与文档的可公开性、提交身份

## 背景

项目将在"初步跑通"后作为**开源小项目**上传 GitHub。但本仓库同时承载了**教育研习材料**
（研习设计、问卷、知情同意书）与**个人调研记录**（学校信息、决策记录），
并且现有 git 历史中的提交身份包含个人邮箱。直接整仓公开会造成隐私泄漏与研究材料外泄。

## 决策

1. **只公开软件本身**：`src/`、`tests/`、`scripts/`、`evals/cases/`、`.github/` 与构建配置
2. **研究类与个人类材料一律不公开**：`docs/`、`notes/`、`TASKS.md`、`CODEBASE_NOTES.md`、
   `AGENTS.md`、`publish/`、`tools/`、`backend/`、`content/`、`.env`
3. **新建干净仓库**：在新目录 `git init`，只保留**一次**初始提交；**不使用现有历史**
   （避免带出个人邮箱与历史身份）
4. **提交身份用 GitHub noreply 邮箱**；LICENSE 的版权持有人由开发者自行决定
5. **许可：MIT**
6. **发布时机**：M3 完成（Agent 循环 + 最小对话界面，本地可完整走通）
7. **发布工具**：`publish/publish_github.ps1`——白名单复制 + 自动生成公开版
   README/LICENSE/.gitignore + **强制安全扫描** + 单次提交；**不代做 push**（出网属人工操作）

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 整仓公开（含研究材料） | 会外泄研习材料与学校信息；指导教师明确要求学校匿名 |
| 公开现有历史但改写邮箱 | 仍会带出内部提交信息与文档演进痕迹；改写历史属破坏性操作、风险高 |
| 手动挑选文件上传 | 易漏、易反复；白名单脚本可重复执行、可自动扫描 |
| 用 `git filter-repo` 清洗历史 | 本场景不需要历史，不如新起一个干净仓库简单可靠 |

## 后果

- ✅ 公开仓库与内部仓库解耦：内部可以继续自由记录研究材料
- ✅ 每次发布都可重复（改完代码再跑一次脚本即可）
- ✅ 安全扫描把"失误造成泄漏"变成"脚本拒绝执行"
- ⚠️ 公开仓库不含架构与开发文档（仅公开版 README）；若将来希望公开部分文档，
  需在此 ADR 追加范围并同步更新脚本白名单
- ⚠️ 公开仓库的代码注释不得残留研究语境（"研习/问卷/实习"等）——已中性化，
  并由扫描规则持续保证
