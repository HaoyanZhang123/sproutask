# ADR-0006：分发形态——便携版与安装版并存

- **状态**：**Accepted（2026-09-27 用户拍板）**
- **日期**：2026-09-27
- **影响**：`electron-builder.yml`（`win.target` 增加 `nsis`）、`docs/ARCHITECTURE.md` §10、
  使用指南、发布产物与体积

## 背景

`docs/ARCHITECTURE.md` §10 原先只写"Windows：`portable` 便携版（免安装，规避机房权限）"，
便携版已按此交付，并发布到 GitHub Release（v0.1.0-alpha）。

用户随后提出要做"一键安装 exe"：装机更方便、有开始菜单/桌面快捷方式、能正常卸载。
但**机房场景可能既没有安装权限、也不希望留下安装痕迹**，所以安装版不能取代便携版。
两种形态的服务对象不同，需要并存而不是二选一。

## 决策

1. `win.target` **同时产出** `portable` 与 `nsis`；两者文件名必须区分，否则都是 `.exe` 会冲突：
   - 便携版：`SproutAsk-0.1.0-win-x64.exe`
   - 安装版：`SproutAsk-Setup-0.1.0-x64.exe`
2. NSIS 采用 **per-user + oneClick + 不提权**（装到 `%LOCALAPPDATA%\Programs\sproutask`）：
   双击即装、不需要管理员权限，避免踩中要规避的机房限制。
   代价：只给**当前用户**装；机房多用户共用一台机器时需每人各装一次（此时仍推荐便携版）。
3. `deleteAppDataOnUninstall: false`：**卸载不删** `%APPDATA%\sproutask\config.json`——
   那里面有用户的 API Key，而且安装版与便携版**共用同一个 userData 目录**，
   删了会连带毁掉便携版的配置。
4. 安装版与便携版**功能完全一致**（同一个 `app.asar`），差别只在安装方式与快捷方式。
5. 仍然**不做代码签名与自定义图标**（沿用打包那一步记录在案的已知缺口）：
   安装包同样会触发 SmartScreen 提示，正式分发前必须补上。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 只保留便携版 | 用户明确需要"一键安装"；普通用户找文件、每次解压的体验差 |
| 只做安装版 | 机房可能禁止安装、也不留痕；便携版是无权限环境的兜底 |
| perMachine（装到 `Program Files`） | 需要管理员权限，正好踩中要规避的机房限制 |
| 卸载时删除 userData | 会删掉用户的 API Key，并破坏便携版配置（两者共用目录） |
| 现在就买代码签名证书 | 成本与流程超出当前阶段；先记为"正式分发前置"（已记在打包与首次运行配置的已知缺口里） |

## 后果

- ✅ 两条分发路径各就各位：无权限/机房 → 便携版；自己的电脑 → 安装版
- ✅ 安装版有开始菜单/桌面快捷方式、能正常卸载，符合普通用户习惯
- ⚠️ 构建时间与产物体积增加（多一个约 70 MB 的 Setup 包）
- ⚠️ 未签名：安装时同样会弹"已保护你的电脑"，说明里必须写清这一点
- ⚠️ **代码签名暂不做（2026-09-27 用户拍板）**：签名证书需向 CA 购买并通过实名验证
  （传统 OV 证书约 ¥1000+/年，2023 年后还必须存硬件令牌；Azure Trusted Signing 约 $9.99/月；
  SignPath 对开源项目免费）。当前阶段（小范围试用、教师在场、说明里写清"更多信息 → 仍要运行"）
  不构成阻塞；**正式对外分发前再补**。
- ⚠️ oneClick 模式没有"选择安装目录"这一步；将来若要允许选目录，需改成多步向导（`oneClick: false`）
- ⚠️ 验证安装版会**真的在本机装入程序**，验证完必须卸载（本次已按此执行并记录）
