# ADR-0003：内容格式与本地存储实现

- **状态**：决策一（内容格式）**Proposed（待定）**；决策二（存储）**Accepted（2026-09-27）**；
  决策三（折叠标记）**Accepted（2026-09）**
- **日期**：2026-09（决策二于 2026-09-27 拍板）

## 背景

两个技术选择尚未定案，但它们会同时影响多条需求，因此单独记录。

## 决策一：知识点等教学内容用什么格式

| 方案 | 优点 | 缺点 |
|---|---|---|
| **YAML + Zod 校验** | 人可读、可写中文注释、教师能改；CI 可校验引用完整性与前置知识成环 | 需要解析依赖；缩进敏感 |
| JSON | 机器最友好、解析零风险 | 手写易错、不能注释、教师维护体验差 |
| Markdown + frontmatter | 适合长文本，便于直接写教材原文 | 结构化字段（前置知识、误区列表）表达别扭 |

**倾向**：YAML + Zod。**但未定案**——取决于实际录入后的手感（会先做小样本试录）。

## 决策二：学情与对话日志存哪 —— ✅ **已定：JSONL 文件（2026-09-27 用户拍板）**

| 方案 | 优点 | 缺点 |
|---|---|---|
| SQLite（better-sqlite3） | 查询聚合方便（学情雷达、统计）；事务可靠 | **原生模块**需按 Electron 版本编译，配置有门槛，且属"新增依赖"需单独同意 |
| **JSONL 文件（采用）** | 零依赖、可读、易调试、无编译问题；教学研究逐轮编码可直接用 Python/pandas 读 | 统计要自己写；数据量大后变慢；将来迁移会返工 |

**决定**：用 **JSONL**。理由（按用户关心的"长远与效果"排序）：

1. **规模匹配**：一个学生一台机器、一天几十轮、一学年几万轮——JSONL 完全够；
   没有并发、没有多用户查询，"SQLite 的强项"在这个产品里用不上。
2. **零新依赖**：SQLite 要引入原生依赖并为 Electron ABI 重编译，会给打包、CI 与"干净机器可复现"都添麻烦；
   JSONL 只用 `node:fs`。
3. **可核对**：纯文本能直接打开、备份、diff；教学研究分析（RQ2 的逐轮编码）用 pandas 一行读入。
4. **可逆**：正因为有 `StudentStore` 接口，将来真需要聚合查询时只换实现文件，
   历史 JSONL 一次性导入即可——选了 JSONL 不会锁死。

**实现时要定的两条**（写进存储需求的验收标准）：
- **文件切分**：按 `studentId` 分目录、按会话一个文件（便于单会话导出与匿名化引用）
- **写入可靠性**：追加写 + 每条一行完整 JSON（崩溃最多丢最后一行）；写入前后不重排历史

## 决策三：正文里的"可折叠答案"用什么标记（2026-09 定案，Accepted）

**背景**：方案 D 要求教材里的"想一想 / 讨论 / 答案"以折叠块呈现，答案默认收起。
这需要内容文件与渲染层对"哪一段是答案"有共识。

**决定**：用纯文本围栏标记，而不是 HTML 或富文本格式。

```
普通段落直接写
:::think 想一想       ← 可折叠的思考题（默认展开）
…
:::
:::answer             ← 答案（默认收起）
…
:::
```

**理由**：

1. **渲染层不用 `v-html`**：教材内容可能是他人编写的文件，注入 HTML 即 XSS 面；
   结构化区块 + Vue 模板输出，从根上不需要净化器。
2. 不引入第三方 Markdown 渲染器（少一份供应链与体积），也避免"教材排版需求无限扩张"。
3. 纯文本标记对内容作者（教师）最友好：能直接用文本编辑器改，写错了一眼看得出来。
4. 解析是**纯函数**（`src/shared/section-blocks.ts`），可离线单测，主进程与渲染进程共用同一份逻辑。

**宽容策略**：未闭合的块退化为普通文本——宁可让内容多显示，也不能因为少写一个 `:::` 就把整节内容静默藏起来。

**后果**：

- 内容工程（教材文本提取与入库）导出教材文本时，需要把答案部分按上述标记包起来（人工核对一次）
- 提示词层注入前会剥掉标记行，只把文字交给模型（折叠块加"（想一想）/（参考答案）"标注）
- 将来若要做富文本排版，应扩展本约定而不是换成 HTML 直出

> **2026-09-27 追加（真教材入库前）**：实测人教版 2024 版教材，"想一想，议一议 / 讨论"**没有印答案**
> （讨论的答案写在正文里），与占位文本的形态不同。用户拍板：**按我们自己的设计来**——
> 内容工程把教材内容**适配到本约定的折叠块结构**（由我们决定"哪一段算答案"），
> **不照搬教材排版**，渲染层设计不变。

## 当前处置（关键设计）

两个选择都被隔离在**接口**之后，因此暂不定案不阻塞任何开发：

```ts
interface ContentRepository { getUnit(); listKnowledgePoints(); getKnowledgePoint(); getSectionText() }
interface StudentStore      { upsertStudent(); createSession(); appendTurn(); getMastery(); setMasteryState() … }
```

- 上层（Agent 循环、界面、导出）**只依赖接口**
- 决策落地时：新增一个实现文件 + 在主进程注入，**其余代码零改动**
- 禁止在业务代码里直接 `new` 具体实现，也禁止直接读写内容文件/数据库
