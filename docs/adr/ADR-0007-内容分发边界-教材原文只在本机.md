# ADR-0007：内容分发边界——教材原文只在本机

- **状态**：**Accepted（2026-09-27 用户拍板，方案 A）**
- **日期**：2026-09-27
- **影响**：`electron-builder.yml`（`extraResources` 置空）、`docs/ARCHITECTURE.md` §10、
  内容工程（教材入库流程）、学生试用形态

## 背景

用户提供了人教版《生物学》七年级上册的 PDF。**实测**（PyMuPDF 渲染 + Windows 内置 OCR）：
该 PDF 是**扫描版，无文字层**，且**每一页页脚都印着**：
> 版权所有 · 侵权必究　仅供个人学习使用，未经授权不得另做他用

而项目原本的计划（`docs/ARCHITECTURE.md` §10）写的是
"教学内容（`content/units` 结构 + **教材原文**）经 `extraResources` 随包分发"。
`electron-builder.yml` 里也确有 `extraResources: from: content`。

也就是说：**真教材一旦入库，下一次打包就会把原文塞进发给学生的 exe**——
这正好落在许可明令禁止的"他用"上。这是一处必须显式处理的合规边界，而不是技术细节。

## 决策（方案 A）

1. **教材原文只允许存在于本机**：`content/textbook/`（已在 `.gitignore`，不进 git）。
   **绝不随包分发**，也绝不进公开仓库。
2. **打包配置不得整体映射 `content/`**：`extraResources` 置空；将来若要随包，
   只能单独映射"我们自己编写的结构"`content/units/`（那是本项目的智力成果）。
3. **课程标准同理**：只入库"条目编号 + 短引用"用于约束层，不整本随包。
4. **学生试用的形态**：学生用**自己的纸质课本**（或学校提供的电子教材）；
   app 侧提供"单元结构 + 知识点 + 常见误区 + 课标要求 + 位置指引"，
   **不向学生机器分发教材原文**。
   教师本人的机器（本机）可以完整使用原文（个人学习用途）。
5. **把规则变成测试**：`tests/packaging-guard.test.ts` 会检查打包配置
   （不得 `from: content`、不得出现 `content/textbook`）。想改规则必须先改测试并说明理由。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 把原文打包进分发包（原计划） | 属于许可明令禁止的"他用"：向 30–45 名学生提供复制件 |
| **"藏起来、别让人发现我们怎么用"** | ① 不降低任何风险，只把"善意使用中的边界问题"变成"刻意隐瞒"，性质完全不同；② 技术上做不到——文件在本机、app 有日志、公开仓库有提交历史，任何"隐藏"设计都只是自欺；③ 本项目的合规姿势本来就靠"原文永不外流"自然达成，不需要遮掩 |
| 连本机也不放原文（只放结构+位置） | 会让"每句话都有出处"退化为"指路"，模型无法引用原文；本机自用属许可允许的"个人学习"，没必要自我阉割 |
| 现在就去取得出版许可 | 值得做，但不是当前阻塞项：先把边界守住，需要随包时再走许可流程（学校/教研室通常有渠道） |

## 后果

- ✅ 公开仓库与分发包里**一个字教材原文都没有**（发布扫描本来就硬拦 `content/` 与二进制）
- ✅ 教师端可完整使用原文；学生的 app 通过"结构 + 知识点 + 位置"仍能开展引导式对话
- ⚠️ **学生端看不到原文**：阅读视图在学生机器上只能显示知识点与位置，不能显示正文；
  若试用需要原文，要么学生手边有纸质课本，要么先取得书面许可
- ⚠️ 教材是**扫描版**：入库必须走 OCR（本机已用 Windows 内置 OCR 验证可行），
  识别结果需教师逐条审改（与 `content/README.md` 的"AI 起草 + 教师审改"原则一致）
- ⚠️ 将来若要把 `content/units/` 随包，需同步更新本 ADR 与打包守卫测试
