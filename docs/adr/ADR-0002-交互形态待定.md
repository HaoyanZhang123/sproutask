# ADR-0002：交互形态——关卡式 / 对话式 / 混合 / 对话+教材视图

- **状态**：**Proposed（待拍板 Q5）**
- **日期**：2026-09（2026-09 追加方案 D）
- **影响**：M4（F-009、F-013）

## 背景

早期设计把"知识点闯关"当作 Agent 的核心机制（认为它是 Agent 与聊天机器人的分水岭），
但开发者对"关卡"这种形态存疑：初中生是否会因此觉得幼稚？教师是否接受"游戏化"包装？
"闯关地图"是否只是好看而增加实现与维护成本？

## 候选方案（四个）

### 方案 A：关卡式（显式编排）
- 教师预先为知识点编排"关卡"（每个关卡含诊断问、引导问、变式题、过关标准）
- 界面提供闯关地图与进度可视化；Agent 按关卡推进并结算
- ✅ 教学路径可控、进度可见、研习数据规整（每关的通过率）
- ⚠️ 编排工作量大；游戏化包装可能不被师生接受；灵活性低（学生跳不过去）

### 方案 B：对话式引导（无显式关卡）
- 教师只提供**知识点清单 + 前置关系 + 常见误区**；不编排任务序列
- Agent 依据掌握度与教学进度，自主决定下一步问什么、何时给提示、何时推进
- ✅ 编排负担小；交互自然；更贴近"家教"而非"游戏"
- ⚠️ 过程不易可视化；Agent 的策略质量更依赖提示词工程；研习对比实验的条件不易控制

### 方案 C：混合（B 为底，A 为可选皮肤）
- 领域层只维护"知识点 + 掌握度"，编排层可选：教师想用关卡就填关卡定义，不想用就纯对话
- ✅ 两种形态共用同一地基，随时可切换
- ⚠️ 需要多写一层编排抽象（但接口很薄）

### 方案 D：对话引导 + 教材阅读视图（2026-09 新增，借鉴参考项目而来）
- **不游戏化、不编排关卡**：左侧/上方是**教材原文阅读视图**，右侧/下方是 Agent 对话
- 教材中的"想一想 / 讨论 / 答案"采用**折叠块**：答案默认收起，学生先自己答、再展开对照
- Agent 回答里提到出处（"见第四章第一节"）时，**教材视图自动滚动并高亮对应段落**
- 学生也可以在阅读视图里划选一段文字 → 直接送给 Agent 提问
- ✅ 没有"幼稚的游戏化"风险，教师容易接受；有"学习场景感"（对照教材）而非"聊天感"；
  与"答案有出处"这条 P0 原则天然咬合；实现上复用成熟的 Markdown 阅读器交互模式
  （折叠块 / 全文搜索高亮 / 滚动定位），技术风险低
- ⚠️ 需要维护"教材原文 → 结构化 Markdown"的内容管线（含把答案部分标成可折叠）；
  界面比纯聊天复杂；需要处理"对话与教材视图的联动"（滚动/高亮同步）

**参考依据**：`notes/reference/markdown-reader-flutter-借鉴.md` §2.1 —— 该项目的折叠块
（`<details>`，实测 1128 处、展开状态跨回收保持）、中文全文搜索命中高亮、会话与滚动位置记忆，
恰好覆盖方案 D 所需的交互；其滚动位置恢复的多轮收敛算法可直接复用。

## 当前处置

**决策尚未作出（A/B/C/D 四选一，或组合）。** 为不阻塞开发，已采取以下措施：

1. "关卡"**不写入领域契约**（`src/core/domain` 只有教材 / 知识点 / 掌握度 / 会话）
2. M3（Agent 循环）与 M4 的"掌握度状态机"按方案 B 实现——这是**四种方案的公共部分**，
   无论最终选哪个都不白做
3. 方案 D 所需的教材阅读视图已登记为候选需求 **F-013**（见 `docs/ROADMAP.md`），
   待 Q5 拍板后决定是否在 M4 落地
4. 若最终选 A 或 C，再于 M4 新增 `src/core/orchestration/` 编排层，**不改动已完成的代码**

## 决策所需信息

到校后可帮助判断：
- 学生年龄段的实际接受度（初一 vs 初二差异）
- 指导教师对"游戏化"的态度（方案 A 的主要风险点）
- 研习是否需要"每关通过率"这类规整数据（倾向 A），还是更看重对话质量分析（倾向 B/D）
- 学生是否愿意/习惯对照教材原文（若愿意，方案 D 的收益最大；若学生只看对话不看教材，D 的复杂度就白付了）
- 机房场景下"双栏（教材 + 对话）"在小屏幕上是否够用（可能退化为标签页切换）
