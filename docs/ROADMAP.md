# 路线图（ROADMAP）

> 本文件管**里程碑定义、需求编号（F-0XX）与待决策清单**。
> **进度状态一律以 `docs/PROGRESS.md` 为准**（唯一事实来源），本表不重复维护状态。
> **需求编号规则**：`F-0XX`，每条需求对应 `docs/specs/F-0XX-*.md`。

## 里程碑定义

| 里程碑 | 内容 |
|---|---|
| **M0 骨架** | 仓库结构、构建配置、CI、文档体系、领域契约、冒烟测试 |
| **M1 提示词与 LLM 客户端** | 分层提示词 v1、DeepSeek 流式客户端、评测集与 `pnpm eval` |
| **M2 内容工程（全册）** | 教材与课标文本提取、内容格式定案、全册结构化入库、知识点与课标映射、内容校验 |
| **M3 Agent MVP** | 意图询问（四选一）→ `buildStudyScope` 装配上下文 → Agent 循环 + 工具 + 最小界面 |
| **M4 交互与学情** | 方案 D 界面（对话 + 可折叠教材视图）、掌握度状态机、存储实现 |
| **M5 问卷与合规** | 前后测问卷、知情同意材料、使用流程（受控环境引导） |
| **M6 打包分发与试用** | exe 便携版、dmg（CI）、首次运行配置、班级试用与数据整理 |

> 各里程碑的**当前状态**见 `docs/PROGRESS.md` 第 3 节。

## 建议的开发顺序

1. **M1**（不依赖任何未定项）：先让 Agent "会说话、有教学性格"，跑通评测
2. **M3 前半**（不依赖 Q3/Q4/Q6）：意图询问 + 最小对话界面，用内存态假数据即可
3. **M2**（一旦确认教材版本与 Q3/Q6 就开工）：全册入库是试用能否开始的前提
4. **M4**：方案 D 界面与掌握度
5. **M5**：问卷与知情同意（可与 M2/M4 并行，但**必须早于试用**）
6. **M6**：打包、试用、数据整理

> 关键路径：**教材版本确认 → M2 内容工程 → 试用**。这一环最依赖外部信息，到校后第一周就要落实。
