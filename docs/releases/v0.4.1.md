# 芽问 SproutAsk v0.4.1

> 发布日期：2026-11-08。可用性修复版本：把「做不了题」这一类问题从根上修掉。安装包未签名。

## 中文

这一版几乎全部在修同一件事：**学生点了提交，却拿不到反馈**。排查下来是六处各自独立的缺陷叠在一起，任何一处都会让整条链路断掉。

**变更概览**：新增 2 项 · 优化 3 项 · 修复 8 项

### 新增

- **全链路自动走查**：按真实入口进每个页面，把页面上真实渲染出来的可点按钮逐个点过去，记录点击失败、白屏、内部术语泄露与失败提示。这一版实测 32 个动作、0 个有问题。此前几次线上问题都是"某个具体操作一按就出错"，人工走查覆盖不到边角。
- **真实内容包逐题回归**：用内容包里自己列出的"可接受作答"跑全部 45 道文字题与 41 道选择题，要求都必须判得出、且产出学习证据。"某类题型永远判不清"这种缺陷以后会被 CI 直接拦住。

### 优化

- **换节语义**：换题只在本节内进行。这一节的题做完后，主按钮从「再答一次」变成「学完这一节」，并提示可以去目录挑下一节，不再自动跨节。
- **启动可诊断**：闪屏文案区分首次与非首次启动，等待超过 15 秒会显示已等秒数；宿主写出 `launch-phases.json` 记录各阶段耗时，下次卡顿可直接定位卡在哪一步。
- **导出保存位置**：导出学习记录时由你选择保存文件夹；删除学习记录前会先自动备份到你所选的位置，备份失败就不删。

### 修复

- **作答被静默丢弃**：请求编号用页内计数器，刷新后从 1 重新计数，撞上历史编号后被当成"重复提交"直接返回旧结果，这次作答根本没有落库——随后写评分状态时找不到记录，界面显示「找不到这项内容」。现在请求编号跨刷新、跨重启都唯一。
- **撞号不再静默去重**：同一编号携带不同内容时明确拒绝，而不是悄悄丢掉新数据。
- **换节后批改被拒**（「这次操作被安全检查拒绝」）：会话绑定的是上一节的概念，换到另一节的题后，批改按题目所属概念去找学习记录却找不到。现在换节会正确新开会话，不再把旧概念和新题目拼在一起。
- **正常作答永远判不清**：规则批改的匹配阈值与评分要点的书写形态不匹配，实测"自然表达但正确"只有 0.42~0.47（判不清），而"只把词罗列一遍"却有 0.54~0.73（判对）——等于奖励罗列、惩罚正常表达。已按实测数据重新标定，并去掉要点里的括注干扰。
- **有成绩却被丢弃**：批改判不清时，界面直接走失败分支，把已经生成好的讲评整个丢掉，只显示「提交没有完成」。现在有内容就展示。
- **提交被永久卡死**（「内容已经有了更新」）：提交要求版本号严格相等，但页面版本号常落后于后台（上一轮反馈还没回来就点了下一题），一旦落后就再也交不上去。现在只拒绝"超前"的版本号。
- **导出/删除入口是空的**：客户端里这两个功能原本是写死的"未接入"占位，现在真正接通。
- **学生界面露出内部术语**：设置页曾显示「DSH 内核」；出处弹层曾显示「PDF 页序（1 基）」「印刷页码」，没有课本页码时会回退成 PDF 页号（内容包 281 条来源里有 98 条没有课本页码）。现已改为学生能懂的说法，并把 `PDF`、`页序`、`印刷页码` 等加进文案禁词表。

### 质量门

CI 保持全绿：`typecheck`、全量单元测试、`check:tracked`、`contract:lock:verify`、内容包校验，以及构建产物与已提交文件一致。

### 重要说明

- 安装包**未做代码签名**，Windows 会提示「未知发布者」；发布页附 `SHA256SUMS`。
- 原生桌面壳需要 **WebView2 Runtime**（Windows 11 自带；Windows 10 多数已随 Edge 安装）。
- 规则批改只做关键词覆盖、不做语义理解：写得过短或换用完全不同的说法时仍可能判不清；此时会如实说"判不清"，不会误判为错。
- 未做另一台干净机验证，未做学习效果实验——不声称提升理解或成绩。
- 此前因缺陷丢失的历史作答无法恢复（那次从未写入本地记录）。

## English

This release is almost entirely about one thing: **students submitted an answer and never got feedback**. Six independent defects were stacked on the same path, and any single one broke the whole chain.

**Summary**: Added 2 · Improved 3 · Fixed 8

### Added

- **End-to-end click-through survey**: enters every page through its real entry point, enumerates the buttons actually rendered, clicks each one and records click failures, blank screens, leaked internal terms and failure banners. This release measured 32 actions with zero problems. Earlier production issues were all "one specific action fails", which manual walkthroughs never reached.
- **Per-activity regression against the real content pack**: runs all 45 free-text and 41 multiple-choice activities using the content pack's own accepted answers, requiring that each is graded and produces learning evidence. A whole question type silently becoming ungradable is now caught by CI.

### Improved

- **Section-scoped navigation**: "next question" stays within the current section. When a section's last question is answered, the primary action becomes "finish this section" with a hint to pick the next section from the index, instead of silently crossing sections.
- **Diagnosable startup**: the splash distinguishes first run from normal startup and shows elapsed seconds past 15s; the host writes `launch-phases.json` with per-phase timings so a slow start can be located.
- **Export destination**: exporting learning records lets the student choose a folder; deleting backs up to the chosen folder first and aborts if the backup fails.

### Fixed

- **Answers silently dropped**: request ids came from a per-page counter that restarted at 1 after a reload, collided with historical ids and were treated as duplicates, so the new answer was never persisted — grading then could not find it and the UI said "can't find this content". Request ids are now unique across reloads and restarts.
- **Collisions no longer deduplicated silently**: a reused id carrying different content is rejected instead of dropping the new data.
- **Grading rejected after switching sections** ("this action was blocked by a safety check"): the session was bound to the previous section's concept, so grading looked for a progress record under the new question's concept and found none. Switching sections now correctly starts a new session instead of pairing an old concept with a new question.
- **Correct answers permanently ungradable**: the rule grader's match threshold did not fit how rubric criteria are written. Measured: natural but correct answers scored 0.42–0.47 (ungradable) while merely listing keywords scored 0.54–0.73 (graded correct) — rewarding keyword dumps and punishing normal writing. Recalibrated from measurement, with parenthetical notes stripped before matching.
- **Generated feedback discarded**: when the grader could not decide, the UI took the failure branch and threw away the already-produced feedback, showing only "submission incomplete". Feedback is now shown whenever it exists.
- **Submissions permanently stuck** ("content has been updated"): submission required an exactly equal revision, but the page often lags behind (e.g. the previous round's feedback has not arrived yet), making the question impossible to submit afterwards. Only an ahead-of-server revision is rejected now.
- **Export/delete were stubs**: both were hardcoded "not wired" placeholders in the client; they are now actually connected.
- **Internal terms shown to students**: settings displayed "DSH kernel"; the source popover displayed "PDF page order (1-based)" and "printed page", and fell back to a PDF page number when no textbook page existed (98 of 281 source refs have none). Rewritten in student language, with `PDF`, `page order` and `printed page` added to the copy-guard word list.

### Quality gates

CI stays green: `typecheck`, the full unit suite, `check:tracked`, `contract:lock:verify`, content-pack validation, and consistency between build artifacts and committed files.

### Notes

- The installer is **not code-signed**; Windows shows "unknown publisher". `SHA256SUMS` is attached to the release.
- The native desktop shell requires **WebView2 Runtime** (bundled with Windows 11; usually present on Windows 10 via Edge).
- Rule grading is keyword coverage, not semantic understanding: very short answers or entirely different wording may still be ungradable. In that case it says so honestly instead of marking the answer wrong.
- No clean-machine verification and no learning-outcome study — no claim of improved understanding or grades.
- Answers lost to the defects above cannot be recovered; they were never written to the local record.
