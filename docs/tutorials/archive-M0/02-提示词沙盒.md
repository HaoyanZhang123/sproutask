## 为什么先做这个？

一个 AI 学习 Agent 最难、最有研习价值的部分不是界面，而是**提示词工程**——怎么让 AI 忍住不直接给答案、怎么识别"帮我写作业"的意图、怎么在超纲时把学生拉回教材。

这一篇的产物**不是最终代码**，而是**一份调教好的系统提示词**——它将来会原样搬进 TypeScript 写的 Agent 本体。这个 FastAPI 沙盒后续还能复用为"教师基站"（收日志、生成学情雷达）。

## 第 2 步：写系统提示词（prompts.py）

新建 `backend/prompts.py`。这是整个产品的"教学设计核心"，第一版（后面会反复打磨）：

```python
SYSTEM_PROMPT = """你叫"小芽"，是一名初中生物学习伙伴。你的知识范围仅限于初中生物教材内容。

【核心规则——必须严格遵守】
1. 永不直接给出完整答案。用提问引导学生自己发现答案（苏格拉底式教学）。
2. 每次只推进一小步：先问一个诊断性问题了解学生的想法，根据回答给"提示"而非"结论"。
3. 学生连续 2 次答不出来时，才给出部分提示，并把问题拆得更简单。
4. 如果学生直接索要作业或试卷答案，不要拒绝他，而是说："这道题我们一起来分析！你先说说它考的是哪个知识点？"
5. 如果问题超出初中生物教材范围（比如问游戏、问高中知识），说："这个超出课本范围啦，建议去问老师！不过我可以给你讲讲课本里相关的……"并引导回教材内容。

【表达要求】
- 语气亲切活泼，像一个大姐姐/大哥哥，多用 emoji 🌱
- 每轮回复不超过 150 字（初中生没耐心看长文）
- 多用生活类比（如"线粒体是细胞的充电宝"）
- 引用教材时说明"教材第X章第X节有讲到哦"（现阶段你知道章节名即可，教程03会接入真实教材内容）

【安全红线】
- 不谈论与生物学习无关的敏感话题
- 绝不索要学生的姓名、学校、联系方式等个人信息
"""
```

**设计要点解读**（研习报告可用）：
- 规则 1-3 = Khanmigo 的"引导优于告知"
- 规则 4 = 不硬拒绝（避免学生流失），而是转化意图
- 150 字限制 = 匹配初中生注意力
- "教程03接入真实教材" = 现在是"裸模型"阶段，AI 还不知道教材具体内容

## 第 3 步：写沙盒（main.py）

新建 `backend/main.py`：

```python
import os
from dotenv import load_dotenv
from fastapi import FastAPI
from pydantic import BaseModel
from openai import OpenAI

from prompts import SYSTEM_PROMPT

load_dotenv()

client = OpenAI(
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com"
)

app = FastAPI(title="BioBuddy 提示词沙盒")


class ChatRequest(BaseModel):
    message: str                 # 学生这轮说的话
    history: list[dict] = []     # 之前的对话记录


class ChatResponse(BaseModel):
    reply: str


@app.post("/chat", response_model=ChatResponse)
def chat(req: ChatRequest):
    messages = [{"role": "system", "content": SYSTEM_PROMPT}]
    messages.extend(req.history)
    messages.append({"role": "user", "content": req.message})

    response = client.chat.completions.create(
        model="deepseek-chat",
        messages=messages,
        temperature=0.3,   # 低温=回答更稳定，教学场景要稳不要飘
    )
    return ChatResponse(reply=response.choices[0].message.content)


@app.get("/")
def root():
    return {"status": "BioBuddy 沙盒运行中 🌱"}
```

**逐段解读**：
- 两个 `BaseModel` 类 = 定义接口的"收件格式"，FastAPI 自动校验并生成文档页
- `history` 由前端每次把对话发回来（调试阶段最简方案；正式 Agent 会改用本地 SQLite 管会话）
- `temperature=0.3`：教学场景要稳定

## 第 7 步：为 Agent 化做准备（本篇新增）

真正的 Agent 不只是"会说话"，还要会**调工具**。先在沙盒里试一下 DeepSeek 的 function calling：

```python
# 加到 main.py 末尾，测试工具调用能力
tools = [{
    "type": "function",
    "function": {
        "name": "search_textbook",
        "description": "在初中生物教材中检索相关段落。当学生问到具体生物知识时调用。",
        "parameters": {
            "type": "object",
            "properties": {"query": {"type": "string", "description": "检索关键词"}},
            "required": ["query"]
        }
    }
}]

response = client.chat.completions.create(
    model="deepseek-chat",
    messages=[
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": "光合作用的原料是什么？"}
    ],
    tools=tools
)
print(response.choices[0].message.tool_calls)   # 看 AI 是否主动要求调用工具
```

✅ 如果打印出 `tool_calls`（AI 主动要求检索教材），说明**工具调用机制可用**——这就是未来 Agent 循环的基础：AI 决定调工具 → 你执行工具 → 把结果喂回给 AI → AI 继续决策。
