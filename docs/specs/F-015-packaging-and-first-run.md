# F-015：打包与首次运行配置

- **里程碑**：M6（打包分发）——提前做，因为它同时是"能不能把软件交给学生"的硬门槛
- **状态**：✅ 已完成（2026-09）
- **依赖**：F-010（界面）、F-013 的接口（存储未实现，不影响打包）

## 1. 目标

让"学生拿到一个 exe，双击、填一个 Key、就能用"这条路真正走通。

**为什么必须先做配置界面**：此前读 API Key 只有两条路——开发期的 `.env`，或打包后的
`userData/config.json`（**能写入它的界面并不存在**）。直接把包装出来发给学生，他打开就连不上模型。

## 2. 交付物

| 产物 | 路径 | 说明 |
|---|---|---|
| 便携版 exe | `release\SproutAsk-0.1.0-win-x64.exe` | **72.3 MB**，免安装（规避学生机房无安装权限的问题） |
| **安装版 exe（NSIS）** | `release\SproutAsk-Setup-0.1.0-x64.exe` | **72.5 MB**，双击即装（装到当前用户目录，不需要管理员权限）；2026-09-27 追加，见 §3.4 |
| 未打包目录 | `release\win-unpacked\` | 同上内容，直接跑 `SproutAsk.exe`（排查用） |
| 配置界面 | `src/renderer/src/components/ConfigPanel.vue` | 首次运行自动弹出，也可从顶栏"设置"进入 |

构建命令：`pnpm build:win`（**一条命令**：先 `electron-vite build` 再 `electron-builder`）。

## 3. 实现要点

### 3.1 首次运行配置（新增）

- **入口**：启动时若检测不到 Key，直接显示配置界面；顶部黄条（文案未改）保留，点"稍后再说"可跳过
- **字段**：API Key（密码框）、高级设置里的接口地址与模型名
- **两个按钮**：「先试连一下」真实发一次最小请求并给出**面向大人的中文说明**
  （Key 无效 / 余额不足 / 网络不通 / 频率限制……）；「保存并开始」写入本机配置
- **保存位置**：系统用户目录 `%APPDATA%\sproutask\config.json`（不写 `.env`、不进安装包）
- **安全红线**：Key 只从界面**流向**主进程，**永不回显**——连 `sk-…abcd` 这种掩码都不给
  （掩码也是密钥信息）。自检里有断言：配置界面与试连结果都不出现任何 Key 片段

### 3.2 打包相关的三处修正（都是实测踩出来的）

1. **`win.signAndEditExecutable: false`**：electron-builder 打包 Windows 时会下载 winCodeSign，
   该压缩包含 macOS 的 `.dylib` 软链接；在没有管理员权限、也没开"开发者模式"的机器上，
   7-Zip 解压报"客户端没有所需的特权"而中断。关掉它只影响"改写 exe 图标/版本信息 + 签名"，
   当前既无自定义图标也未签名，不影响可用性（要做正式签名时需管理员或开发者模式）
2. **打包版不再读 `.env`**：便携版的自解压目录/启动目录都不可信，一个来路不明的 `.env`
   就能顶替用户配置——既意外也不安全。打包版唯一配置来源是用户目录的 `config.json`
3. **诊断文件写到持久目录**：打包版没有控制台，自检结果与启动日志必须落盘；
   便携版的 cwd 是**退出即被删除**的自解压临时目录（实测结果文件因此消失），
   所以打包版优先写用户目录，开发期写当前目录

### 3.3 自检在打包版里必须能跑

- 新增 `SPROUTASK_SELFTEST=1` 下的**结果文件**（`selftest-result.json`）：无控制台时靠它判读
- 断言顺序修正：**"复习模式默认收起阅读区"必须在发消息之前断言**——小芽的回复一旦提到课本位置，
  会触发"出处自动定位"并展开教材区（F-011 的设计行为），发消息之后再断言必然失败
- 改为**轮询等待**（`waitForRenderer`）而不是固定 sleep：界面是异步装配的，
  固定等待在打包版上赶不上（实测踩到）
- 所有注入脚本对"元素不存在"免疫，避免一处脚本抛错让整个自检中断

### 3.4 安装版（NSIS）—— 2026-09-27 追加

决策与取舍见 `docs/adr/ADR-0006`（便携版与安装版并存）。要点：

- `win.target` 同时产出 `portable` 与 `nsis`；`pnpm build:win` 一条命令产出两个文件
- NSIS 选项：`oneClick: true`（双击即装）、`perMachine: false`（装进
  `%LOCALAPPDATA%\Programs\sproutask`，**不需要管理员权限**）、`allowElevation: false`（不弹 UAC）、
  创建桌面与开始菜单快捷方式、`deleteAppDataOnUninstall: false`
  （卸载**不删**用户目录里的 `config.json`——那是用户自己填的 API Key，且与便携版共用同一 userData）
- 安装包**单独命名** `SproutAsk-Setup-<version>-<arch>.exe`：两个目标都是 `.exe`，不区分会冲突
- 与便携版功能完全一致（同一个 `app.asar`）；差别只在安装方式与快捷方式

## 5. 已知缺口（诚实声明）

- **没有自定义图标**：用的是 Electron 默认图标（打包日志明确提示 "default Electron icon is used"）；
  做图标需要 `.ico` 文件，且要注意发布扫描会把二进制文件当作硬失败，需要另行约定
- **没有代码签名**：Windows 首次运行可能弹 SmartScreen 提示，学生需要点"更多信息 → 仍要运行"；
  分发给学生时应在说明里写清这一步。
  **2026-09-27 决定暂不购买证书**（传统证书约 ¥1000+/年且需硬件令牌；Azure Trusted Signing 约 $9.99/月；
  SignPath 对开源项目免费）——当前阶段不构成阻塞，正式对外分发前再补，见 `docs/adr/ADR-0006`
- **打包体积偏大**（72 MB）：`app.asar` 18 MB 里含 vue 的传递依赖（渲染层其实已被 Vite 打包），
  可优化为把 vue/pinia 移到 devDependencies；这属于优化项，未擅自改动
- **`dmg`（macOS）从未构建过**，也没有 Mac 环境；`build:mac` 属未验证路径
- 学生机器上**首次配置要老师/家长帮忙**（要申请 Key、充值）；这部分流程文档化在
  `docs/tutorials/README.md`
- 打包产物**不适合直接进公开仓库**（体积与二进制扫描规则），Release 时作为附件上传
