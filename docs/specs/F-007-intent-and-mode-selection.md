# F-007：意图询问与模式选择流程

- **里程碑**：M3
- **状态**：✅ 已完成（2026-09）
- **依赖**：依赖 F-002（提示词与 LLM 客户端）✅；不依赖 Q3/Q4/Q6 与外部信息

## 1. 目标

实现"打开后 Agent 主动询问 → 学生四选一 → 确定学习位置 → 进入引导"的前置流程。
这是 2026-09 决策的落地：**不猜"这周教到哪"，而是问学生**。

## 2. 用户故事

作为学生，我希望打开程序后有人直接问我想做什么（预习/复习/做题/拓展），而不是面对一个空白输入框；
作为研究者，我希望这个流程可被脚本化测试，也能在终端先跑通，再接图形界面。

## 3. 输入与输出

| 项 | 输出/输入 | 说明 |
|---|---|---|
| 输入 | 学生的自然语言或数字选择 | 如"复习"、"2"、"我想先做几道题" |
| 输入 | 可选位置列表 + 上次位置 | 上次位置来自本地记录（持久化在 F-013 落地） |
| 输出 | `{ mode, position, fallbackUsed }` | 供 `buildStudyScope(position, mode)` 装配上下文 |
| 涉及契约 | `StudyMode`、`StudyPosition`（已存在于领域契约，不新增） | |

## 4. 实现要点

- `src/core/agent/intent.ts`：纯逻辑 + 可注入的 `ask` 回调（便于测试与将来换成界面）
  - `parseStudyMode(input)`：支持标签（预习/复习/做题/拓展）、编号（1–4）、同义词
  - `buildOpeningQuestion({ lastPositionLabel? })`：开场问句（Agent 主动发问，含四个选项）
  - `parsePositionChoice(input, options)`：支持编号、名称、章节 id；空输入回退到"上次位置"
  - `IntentFlow`：状态机 `awaiting-mode → awaiting-position → ready`
- **重问机制**：回答无法识别时重问，超过上限（默认 3 次）则回退到"复习"并标记 `fallbackUsed`
- **位置策略**（Q7 决策）：有上次位置则"直接回车继续上次"，也可手动改
- 终端可体验：`pnpm chat` 开场即走这个流程

## 5. 验收标准

- [x] `parseStudyMode` 对 4 种模式、编号、常见同义词均能正确识别；无关输入返回 null
- [x] `IntentFlow` 正常路径产出 mode + position；不可识别时重问；超限回退并标记
- [x] 位置：仅一个可选位置时自动选定；有上次位置时回车即可继续
- [x] `pnpm chat` 开场出现询问，选完后进入对话且模式生效（提示词体现模式）
- [x] `pnpm typecheck` 与 `pnpm test` 通过
- [x] 合规：不询问、不记录任何个人信息

## 6. 明确不做

- 不做图形界面（M3 后半的 F-010）
- 不做位置持久化（属 F-013 存储实现；本需求通过注入参数支持）
- 不做各模式**内部**的引导策略细化（Q8：待后续细聊）

## 7. 已知缺口与遗留问题

- 模式识别基于关键词规则，学生用非常规说法（如"我想把上次没懂的再搞明白"）可能识别失败
  —— 回退为"复习"并由提示词再确认；后续可在接上 LLM 后改为模型判定
- 位置列表目前由调用方给出；真实的"册/章/节"列表依赖 M2 内容工程
