# F-011：教材阅读视图（可折叠答案 · 搜索高亮 · 出处定位）

- **里程碑**：M4（提前执行：不依赖外部信息，且是方案 D 的另一半）
- **状态**：✅ 已完成（2026-09）
- **依赖**：F-010（最小对话界面）✅、F-007（意图询问）✅

## 1. 目标

把"对话"与"教材"连起来：学生随时能看到正在学的那一节原文，**答案默认收起**（先自己答、再展开对照），
Agent 提到出处时教材区自动定位并高亮。这是方案 D 的第二半，也是"答案必须有出处"这条原则的落地环节。

## 2. 用户故事

- 作为学生，我想先自己想一想，再对照课本里的答案——而不是被直接告知。
- 作为学生，当小芽说"见第四节"时，我希望教材区自己滚过去并高亮，而不是让我翻页去找。
- 作为教师，我想确认"学生看到的解释确实来自教材"，并能用关键词在教材里核对。

## 3. 输入与输出

| 项 | 说明 |
|---|---|
| 输入 | 当前 `StudyScope` 的小节原文（含 `:::think` / `:::answer` 标记）、学习模式 |
| 输出 | 结构化区块（`SectionBlock[]`）、搜索命中片段、滚动定位 |
| 涉及契约 | **不新增领域契约**；新增 `src/shared/section-blocks.ts`（纯函数，见第 4 节） |

## 4. 实现要点

**内容标记约定**（落 `docs/adr/ADR-0003` 的"决策三"）：

```
普通段落直接写
:::think 想一想        ← 可折叠的思考题，默认展开
…
:::
:::answer              ← 答案，默认收起
…
:::
```

**为什么不用 HTML `<details>` 或第三方 Markdown 渲染器**：
1. 渲染层用 Vue 模板输出、**完全不用 `v-html`**——教材内容可能是他人编写的文件，注入 HTML 即 XSS 面；
2. 不引入第三方渲染器，少一份供应链与体积；
3. 纯文本标记对内容作者（教师）最友好，写错了一眼能看出来。

**宽容策略**：未闭合的块**退化为普通文本**——宁可多显示，也不能因为少写一个 `:::` 就把整节内容静默折叠隐藏。

**新的 `src/shared/` 层**：解析器与高亮切分是纯函数，主进程与渲染进程都要用。
它既不能放 `core`（core 是主进程侧领域逻辑，渲染进程不该引），也不适合在两边各写一份（会漂移），
于是单列 `src/shared/`：**零依赖纯代码，三层都可引用**，由测试把关（见验收标准）。

**提示词侧**：`buildTextbookLayer` 会**剥掉标记行**再注入，只把块内文字（含答案）交给模型，
并给折叠块加"（想一想）/（参考答案）"标注。答案必须留在上下文里——引导需要知道正确结论，
"不给答案"靠教学纪律与泄漏护栏约束，不靠藏内容。

**交互**：复习 / 做题模式**默认收起**阅读区（把屏幕让给对话），预习 / 拓展展开；
搜索命中只出现在折叠答案里时**只提示不自动展开**（避免把答案主动推给学生），学生点"展开看看"才展开。

## 6. 明确不做

- 不做逐字流式（F-010 的决策，理由见该 spec）
- 不做 Markdown 富文本（加粗/列表/图片）；教材原文的排版美化留到内容工程落地后按真实样式再做
- 不做多小节同时展示（当前只渲染当前小节；跨节跳转随内容库实现一起做）
- 不做划词提问（方案 D 里列了，属后续交互增强）
- 不做掌握度落库（F-013）

## 7. 已知缺口与遗留问题

- 搜索是**朴素子串匹配**（大小写不敏感），没有分词与近义匹配；中文场景够用，但"线粒体/粒线体"这类
  同义写法搜不到——是否需要引入分词，等真实教材试用后再定
- 折叠状态**不持久化**（刷新/重开会回到默认收起）
- 出处联动只处理"小节标题 / 第X节 / 第X章"三类线索，回复里若只说"书上第三段"则定位不到
- 阅读区目前只显示 `sectionTexts[0]`；多小节/多单元的切换要等内容库（F-006）落地
